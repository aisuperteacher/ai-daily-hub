二、重点更新详解：Qwen Code v0.26.9

1. 官方信息与发布时间

阿里巴巴 / Qwen：稳定版 Release v0.26.9；GitHub 发布记录为 2026 年 11 月 6 日 16:07 UTC，北京时间 11 月 7 日 00:07。发布说明列出 39 个相关 PR，注明没有已知 Breaking Changes。官方 Release

2. 核心变化及技术机制

  • Skills 生命周期管理：Skill ZIP 安装、Web Shell 上传、Daemon 原生安装接口、TypeScript SDK 支持及失败后的安装回执查询。
  • 原子化批量启停：新增 PUT /skills/activation 和 SDK 方法 setUserSkillsActivation，一次可操作 1–100 个用户 Skill，提供偏好保存与传播状态。
  • Managed Agent 可靠性：持久化结构化用户问题、自动化、激活租约续期、Writer 恢复、历史消息缓存以及工具执行锁竞争得到改进。
  • 任务与权限可观测性：PR 自动验证可读取 Review Thread，自动修复拒绝时有机器可读原因；终端通过 OSC 7501 报告 working、blocked、done、error。

安装成功、启用成功、传播到所有执行节点，是三个不同状态。 如果 ZIP 已写入磁盘但客户端在收到回执前断网，不能简单再次安装；应通过尝试标识和安装回执查询后再决定是否重试。这正是分布式事务中“结果未知”的典型问题。

3. 为什么有价值

过去许多 AI Coding Skills 依靠复制文件到目录进行管理。多人、多 Agent、长期执行场景下，容易产生版本漂移、重复安装、激活不一致和故障恢复困难。此次升级把 Skill 逐步升级为可通过 API、SDK、Web UI 管理的工程对象，价值来自部署的可管理性和可恢复性，而不是模型本身更强。

4. 适用业务与产品场景

适用于企业 Skill 市场、Agent 插件平台、团队共享工具、AI 应用开发平台和持续运行的 Coding Agent。例如为多个业务团队提供数据库分析、代码审查、文档生成与日志诊断 Skill，同时需要管理员批量启停、审计及回滚。

5. 对企业架构及开发工作的影响

结合 Spring Boot、Nacos、微服务网关，可把 Skill 生命周期抽象为独立服务：

管理端 / CI → Skill Registry / API → Agent Runtime A / Agent Runtime B
这是建议的逻辑分层示意，不是 Qwen 官方部署拓扑。安装回执、版本控制、激活传播和审计应贯穿各层。

Registry 管理 Skill ID 与版本；安装需幂等键；各 Runtime 上报实际生效版本；权限区分上传、批准、启用和执行；失败时依据回执确认真实状态。对不可信 ZIP，应限制体积、阻止解压目录穿越、审核内容及校验完整性，执行环节保持最小工具权限。

6. 试用步骤与验收标准

在 Windows PowerShell 7 先检查环境：

node --version
npm view @qwen-code/qwen-code version
qwen --version

项目 README 当前要求 Node.js 22 或更高版本。建议测试环境固定版本，而不是直接用 latest 覆盖生产：

npm install -g @qwen-code/qwen-code@0.26.9
qwen --version
  1. 准备无敏感信息的测试 Skill ZIP，记录 SHA-256。
  2. 通过 Web Shell 或 SDK 安装并取得回执。
  3. 启用两个测试 Skill，检查偏好与实际生效状态。
  4. 安装过程中模拟客户端断连，回读安装结果，避免重复提交。
  5. 禁用一个 Skill，验证新会话无法使用，并记录传播延迟。
  6. 模拟失败与回滚，确认旧版本能够恢复。

验收：安装可追踪；相同尝试重试无重复副作用；批量激活状态明确；故障可恢复；禁用后权限行为符合预期。

7. 升级建议与优先级

建议看，建议测试后再升级。无需为这个版本立即迁移整个 AI 编程工具链。Qwen Code 框架采用 Apache-2.0 许可，但模型 API、托管服务、订阅计划须分别核实许可与计费。此版本没有宣布新的模型上下文、Thinking 参数或 Token 价格，不能推测。
