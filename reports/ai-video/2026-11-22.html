01重大更新

01Kling VIDEO 4.0 新增原生 4K 与 10-bit HDR 输出2026-11-19｜Runware API 更新★★★★★

发生了什么

Runware 宣布 Kling VIDEO 4.0 API 新增 4K 输出及 10-bit HDR。支持 3840×2160 横屏、2160×3840 竖屏以及方形、超宽屏规格；HDR 采用 HEVC、BT.2020 与 HLG。此处指 Runware 的接口新增能力，不是宣称可灵底层模型在 11 月 19 日才首次面世。

核心技术变化

从常规 8-bit SDR 交付扩展到可选择更高分辨率和动态范围的生成管线。HDR 涉及亮部、暗部、色彩空间和播放端的正确处理，不只是把画面调得更亮。

相比之前提升

此前 Runware 接口主要提供 720p 和 1080p，如今增加高规格母版输出，有利于二次裁切与调色；分辨率提高不意味着剧情逻辑、手势或角色身份自动正确。

对 AI 短剧制作的具体价值

竖屏人物特写、夜景灯光、服装纹理及需要局部推进的画面可优先使用 4K HDR；大批量镜头应先低规格生成并验收，再为重要镜头制作高清母版。

当前可用性／成本／限制

Runware 已开放相应 API；4K 与 HDR 的实际单次收费需按请求规格和报价核实。HDR MP4 为 10-bit HEVC，旧播放器及 SDR 转换容易发生偏色，因此同时检验 SDR 版。

是否值得立即测试

值得。对同一原创五秒夜景镜头输出 1080p SDR 和 4K HDR，比较肤色、亮部、暗部、移动端兼容性和实际费用。

02HeyGen Avatar 6 Turbo 进入统一 API，角色动作强度可控2026-11-20｜Runware 新接入★★★★★

发生了什么

Runware 新接入 heygen:avatar@6 和 heygen:avatar@6-turbo，后者定位为速度更快、成本更低的版本，两者采用相近的请求参数。Avatar 6 底层模型已在 11 月 17 日推出，此次是第三方统一接口的新增支持。

核心技术变化

可选预设头像、角色参考照片或符合规则的视频参考，通过文本或输入音频驱动嘴型与动作。最多 1200 字符的 positivePrompt 用于手势、表情、姿势与镜头；motionExpressiveness=less 可让动作更克制。

相比之前提升

统一 API 中可对照标准版与 Turbo 的速度、成本及表现。它降低工作流接入复杂度，但 Turbo 较快并不等于每次都能得到与标准版相同的角色一致性。

对 AI 短剧制作的具体价值

双 AI 角色辩论、访谈、悬疑审问和人物独白可以为不同角色设定不同动作强度，并为草稿和正式成片选择不同档位。

当前可用性／成本／限制

支持 1080p、2K 和多种屏幕比例。真实人物的数字分身必须有授权及必要的身份验证，部分真人视频参考受限制。官方更新未给适用全部配置的统一单秒价，须查实际报价。

是否值得立即测试

值得。用同一原创虚构角色及十秒台词，比较标准版与 Turbo 的口型、动作自然度、重复手势、生成速度、价格。

原始来源Runware Changelog ↗ Avatar 6 Turbo API ↗
03Gemini 3.8 Flash TTS：双人对话、情绪和停顿一次规划2026-11-20｜Runware 新接入★★★★★

发生了什么

Runware 增加 google:gemini@3.8-flash-tts，支持单人和双人配音。每次 speech.text 最多 4000 字符，提供 30 个预设声线，双人台词按说话人标签分轮次输入。

核心技术变化

settings.style 控制语气、节奏和情绪；文本支持 laugh、sigh、short pause 等行内标签。语音合成可同时使用台词结构、角色归属和表演指令。

相比之前提升

相较该平台原有 Gemini 3.1 Flash TTS，新版改变了相关控制参数，官方说明自动语言检测覆盖 130 多种语言。需要迁移旧版的 speech.language、temperature、seed 与标签格式，而不是仅改模型 ID。

对 AI 短剧制作的具体价值

可先制作两人争论、审问和情绪反转的对白样音，确定真实停顿与句子时长，再生成视频；减少视频生成之后硬塞配音的问题。

当前可用性／成本／限制

Runware API 已开放，但统一分钟价格未在此次日志确认。预设声音不等于任意真人声音克隆；中文姓名、方言、说话人轮替和情绪需试听。旧 3.1 Flash TTS 预计 2026-12-18 在该平台停用。

是否值得立即测试

强烈建议。用 12 秒双人悬疑对白比较一次双人生成和两次单人生成的时长、角色区分、停顿、情绪及费用。

原始来源Runware 11 月 20 日更新 ↗ Gemini 3.8 Flash TTS API ↗
04HeyGen Video Translate 1.0：多语言配音与口型同步联动2026-11-16｜Runware API 接入★★★★★

发生了什么

Runware 提供 heygen:video-translate@1.0，可翻译视频对白并生成目标语言声轨和对应口型。接口列出 190 个语言代码选项、最多十位说话人的区分参数，以及 speed 和 precision 模式。

核心技术变化

可输入原始视频、自定义配音和 SRT 字幕，使用 startTime/endTime 对局部时间段进行翻译，并按需要分离背景音乐或增强语音；将翻译、配音和 Lip Sync 连接。

相比之前提升

相较传统转写、翻译、TTS、口型修复与合成的完全分离流程，减少音画交接次数并支持按镜头选择速度优先或口型质量优先。

对 AI 短剧制作的具体价值

中文短剧制作英语等海外版本时可尽量复用原始人物表演，同时修改声音与口型；多人镜头中的说话人对应也有明确配置。

当前可用性／成本／限制

已开放第三方 API，成本按平台实际价格和素材时长计算。190 个语言代码不等于所有语言、方言都同等准确；背景音乐分离、情绪和多人同时说话仍需人工复核。肖像和声音必须获得授权。

是否值得立即测试

值得。将一段授权的 15 秒中文双人对话译成英语，逐项检验译文、角色声线、口型、字幕、背景音乐和结算费用。

02值得测试的新技术

05Ideogram 4.6 Precise Edit：局部编辑分镜，不整体重画2026-11-19｜Runware 接入★★★★

发生了什么

Ideogram 4.6 和 Precise Edit 在 Runware 上线。普通生成支持最高 4K；精确编辑接受原图、可选遮罩、参考图片以及指定的像素坐标编辑区域。

核心技术变化

通过 settings.editRegion 和 maskImage 将修改限制在信封、服装徽章、背景门窗等局部位置，尽量保留周围已经验收的画面。

相比之前提升

比每次重新生成整张关键帧更适合定向返工；其稳定性要用原图与输出逐像素/人工对照，不能假设所有未指定区域必然完全不变。

对 AI 短剧制作的具体价值

连载短剧的角色定妆、分镜参考、海报和道具图可保留原始构图，仅改变剧情需要的局部元素，避免污染可信参考资产库。

当前可用性／成本／限制

Precise Edit 支持最高 8192×8192、50MB 的输入图像，区域、比例、参考数量另有约束；费用按模型与实际调用计算。功能主要作用于静态图，不直接解决视频中持续的对象追踪。

是否值得立即测试

建议。只将原创办公室分镜中的红色信封改为蓝色，验证人物脸、发型、服装与门窗结构是否保持。

原始来源Runware Changelog ↗ Ideogram 4.6 Precise Edit ↗
06video-agent：Claude Code 通过帧精确工具进行剪辑与复查GitHub 工程发现｜首次发布日期未核实★★★★★

发生了什么

agamm/video-agent 为 Claude Code 提供 FFmpeg 编辑工具、视频检测、转写、镜头选择、字幕与音乐节拍编辑能力，并可生成注明剪辑理由的 Edit Decision List。

核心技术变化

模型先检查素材，再形成可解释的片段列表，按帧网格处理剪辑、音频时间和字幕，完成渲染后重新检查结果。Skills 封装常见剪辑步骤。

相比之前提升

比让 LLM 临时编写 FFmpeg 命令更具可复现性和可审查性；强调音视频时间基准分离，降低逐镜头截取产生的声音漂移。

对 AI 短剧制作的具体价值

自动制作 15 秒短剧预告、剧情回顾、竖屏裁切、字幕和镜头粗剪；不必每次都用扩散视频模型重新生成已合格的素材。

当前可用性／成本／限制

公开小规模 MIT 项目，依赖 Python 3.11、FFmpeg 等。部分音频转写组件依赖特定平台；可选生成特效需要外部 API。仓库规模尚小，不能当作成熟商用 NLE 替代品。

是否值得立即测试

建议用测试素材。输入三段原创视频，让 Agent 写出有理由的剪辑清单，导出十五秒预告并重新检查音画和字幕。

03开源与论文

07video-agent-runtime：持久化 EditPlan、审批、版本与回滚GitHub 工程研究｜首次发布日期未核实★★★★

发生了什么

开源项目 video-agent-runtime 面向 Claude Code、Codex 和其他 MCP 客户端，提供无界面视频编辑执行环境，整体流程为 Transcript → EditingStrategy → EditPlan/EditPatch → Timeline → Version → Preview → Approval → Export。

核心技术变化

把剪辑修改变成可存档、可验证的编辑中间表示，而不是直接以不可追踪的 FFmpeg 命令修改最终 MP4。通过事务式补丁、审批门槛和渲染版本管理控制更改。

相比之前提升

相比只保存最终成片，系统能知道每次修改的具体目标、参数和版本，便于回滚和审计，也减少多个 Agent 互相覆盖工程的风险。

对 AI 短剧制作的具体价值

字幕 Agent、音效 Agent 与节奏 Agent 可以分别提出修改补丁，经统一校验后再写入正式时间线，适合多集短剧的持续生产和审批。

当前可用性／成本／限制

GitHub 仓库公开，MIT 许可证；仍属于小规模工程项目，复杂特效、专业工程互操作、性能与并发场景需要自行验证。使用本地计算仍有硬件、磁盘和运维成本。

是否值得立即测试

值得研究数据模型。为三镜头视频设计 JSON EditPlan，只改第二镜头时长，检查旧版本是否保留、补丁是否可撤回。

原始来源GitHub：video-agent-runtime ↗
08AVE / Edit in Sync：联合编辑人物外观、声音和口型论文原始日期 2026-10-20｜非今日新品★★★★★

发生了什么

论文 Edit in Sync 提出 AVE 研究框架，针对人物视频的参考引导替换、插入和删除，同时处理音视频模态；研究构建约十万组外观及声音参考数据。

核心技术变化

把画面里的身份、脸部表情与语音条件放进统一音画生成框架，尝试避免换脸、配音、口型修复三个独立步骤积累误差。

相比之前提升

论文报告相较模态分离方案，在编辑真实感、时间一致性和音画同步上取得改善；这些是研究环境结果，不意味着所有商业短剧素材都能无损编辑。

对 AI 短剧制作的具体价值

未来可用于授权数字角色在不同版本中更换外观与声音，尤其是多语言本地化及长期 IP 角色调整；关键仍是同步保持人物身份与情绪。

当前可用性／成本／限制

目前是研究工作，未核实可直接商用的完整 API、权重许可及价格。任何真人的脸部和声线替换都应先获得明确授权。

是否值得立即测试

技术团队可研究；普通创作者先建立联合 QC：人脸身份、声线、嘴型、表情和动作时间是否匹配。

04生产实践

09Gemini Omni Flash 1.1 计划 12 月 3 日退出 Runware2026-11-13 公告｜12 月 3 日计划移除★★★★★

发生了什么

Runware 公告 google:gemini@omni-flash-1.1 将于 2026-12-03 移除，建议迁移到 google:gemini@omni-flash-1.2；继续使用旧 ID 的请求届时会失败。

核心技术变化

新版接口参考图最多十张、单张最大 20MB；文生视频及单首帧图生视频可到十五秒。但部分输入视频文件大小从 48MB 收紧至 32MB，相关时长限制也有变化。

相比之前提升

新版本提高了部分参考和生成长度上限，并非完全向后兼容的无感升级；部分已有素材可能因视频文件限制而失败。

对 AI 短剧制作的具体价值

连载短剧批量脚本若固定旧模型，12 月 3 日可能整个任务队列中断。迁移还需要重新验证角色一致性、时长、音画同步及费用。

当前可用性／成本／限制

新旧版本在过渡期可用于对照；最新费用按模型卡确认。不要只替换 model_id 而忽略输入大小、长度和生成结果差异。

是否值得立即测试

立即检查。搜索全部旧模型 ID，并以五条固定测试镜头比较新旧生成的接口成功率、角色身份、时长、成本和结果。

10Kuku TV AI 微短剧案例：规模化连载和发行比单镜头更重要2026-11-19 披露｜11-20 媒体报道★★★★

发生了什么

印度平台 Kuku TV 披露，以板球为题材的 AI 微短剧 Love Ki Century 自 2026-09-15 上线以来，约 65 天制作超过 700 集，平台声称总观看超过两亿。

核心技术变化

这是平台自有 AI 剧情制作与发行体系的业务实践，强调剧情钩子、角色与主题的持续复用，而不是某个刚发布的视频模型。

相比之前提升

案例展示持续生产系列内容的可能性，但公开报道缺乏单集时长、人力、实际成本和独立审计观看口径，不能推导每人日产量或利润率。

对 AI 短剧制作的具体价值

对一人短剧团队而言，值得借鉴垂直题材、固定角色和持续冲突，围绕同一 StoryBible 编排短篇系列并根据留存数据修正剧情。

当前可用性／成本／限制

平台技术栈和核心接口并未作为通用开发工具开放。700 集、两亿观看均为平台披露并经媒体转述的数据，未独立核验真实成本与收益。

是否值得立即测试

可测试方法，不建议直接追逐数量。先写五集原创故事钩子，制作首集十五秒试播片，持续测量观看完成率和合格镜头成本。

05今天最值得测试的 3 项

01

Gemini 3.8 Flash TTS：双人悬疑对白与情绪停顿

用十二秒两人争论的台词，检验声线稳定、笑声和停顿标签、双人切换及真实时间长度；先把声音确定，再规划分镜。

02

HeyGen Avatar 6 Turbo：标准版与 Turbo A/B 测试

保持台词、背景、分辨率、人物和时长一致，比较费用、生成速度、人物脸部、动作强度、重复手势与口型，而不是只看厂商演示。

03

video-agent：让剪辑 Agent 验证输出

使用三段授权测试片，让 Agent 交付十五秒预告、带理由的 Edit Decision List、字幕时间码及成片复核结果；首先使用不破坏源素材的本地操作。

STEP 07质检、账本和发行QC / Cost / Publishing
  1. 先确认角色和声音，再生成镜头：TTS 可先明确真实台词时长与停顿；视频和数字人镜头应根据实际音频与分镜生成，避免先做视频后强制塞音轨。
  2. 高清输出应该在质量闸门之后：4K HDR 增强母版交付，但不能修复人物身份、错误动作和剧情逻辑。先小规格验证，重要镜头再做高规格输出。
  3. Agent 剪辑需要结构化可回滚流程：video-agent 更强调检查、操作与再次观察；video-agent-runtime 更强调编辑计划、补丁、审批和版本管理。可以组合两种思想。
  4. 海外配音应独立验收：翻译、说话人声线、口型、字幕和背景音乐要逐项核验，API 成功返回并不等于海外版本已经可以发行。
  5. 技术变更与业务效果需要长期证据：记录模型版本、权限、迁移前后测试和合格镜头成本；平台播放总量与模型报价都不能直接代表单集利润。

长期指标：voice_identity_pass、speaker_turn_accuracy、lip_sync_pass、character_consistency_pass、edit_preservation_pass、cost_per_approved_shot、manual_repair_minutes、retention_per_episode。

07今日小练习 · 25 分钟

15 秒双人悬疑短剧：配音 → 表演 → 剪辑 → 审批

目标：将双人对白、数字人动作、分镜时间线与可回滚剪辑计划连接成可检查的小型生产闭环；无 API 额度也可以完成模板。

材料：文本编辑器或 Excel、两名原创虚构人物、办公室背景、两句原创台词；可选 Gemini 3.8 Flash TTS、HeyGen Avatar 6、video-agent、FFmpeg。

0—4 分钟

建立角色与对白

创建 CHAR_A 女主、CHAR_B 男主；男主说“我找到了三个证据”，女主停顿后说“最后一个在哪里？”。记录声线、服装、情绪与场景。

4—8 分钟

制作配音时间线

定义 speaker_id、text、style、audio_start、audio_end，并标记叹息、停顿。有 TTS 权限则生成并记录真实时长；否则标 NOT_TESTED。

8—12 分钟

规划三个五秒镜头

S01 男主展示证据；S02 女主保持沉默的情绪特写；S03 女主质问。明确说话人、可见人物、首尾帧状态。

12—16 分钟

制定数字人 A/B 测试

统一男主台词，比较 Avatar 6 标准与 Turbo 的“三个证据”手势、动作自然度、口型、时间和费用。

16—21 分钟

编写可审批 EditPlan

每个镜头记录文件、起止帧、字幕、音轨、剪辑理由；对“修改 S03 字幕”单独创建 EditPatch，并保存旧版本。

21—25 分钟

检查质量与回滚

检查人脸、手势、音轨、嘴型、字幕、画质和总时长；失败项记录 shot_id、timecode、expected、observed 和 repair_target。

验收标准：两份角色卡、两段对白定义、三个 ShotSpec、一份声音与画面分离时间线、一份 EditPlan、一份 EditPatch、至少八项质量检查。未实际生成的结果只能标 NOT_TESTED，不得标为通过。

思考题：男主说话期间切到女主特写，应该由谁的声音驱动口型？Turbo 较快是否必然更便宜？为什么字幕修改需要重新渲染并检查？HDR 视频在普通 SDR 设备上可能发生什么偏差？

扩展到真实短剧：将三个镜头扩展为十个镜头、六十秒短剧。StoryBible 固定人物；TTS 规划台词与时长；数字人与视频模型负责演出；剪辑 Agent 产生 EditPlan 和可审批补丁；制作两个语言版本，分别归档费用、模型版本、质量与发行数据。

本期结论

当前有价值的进步不只是生成视频更清晰，而是对白可控制、角色表演可分层、镜头修改可回滚、成本能核算，从而形成持续可复现的生产流水线。
