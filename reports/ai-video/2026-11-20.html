01 · 重大更新

Runway Request Tags：按集数、镜头归集生成费用

2026-11-18 · 优先级 ★★★★★
发生了什么

Runway Dev 在 11 月 18 日正式支持请求标签。开发者在生成请求中设置 X-Runway-Tags，再通过 POST /v1/organization/usage 按标签筛选和汇总实际 Credits 用量。Workflow 的标签会传递到每个生成任务。

核心技术变化

生成任务可以使用 episode:ep01、shot:s03、stage:draft 等业务标签归属成本，而不再只有模型和日期。每次请求至多十个标签，支持普通标签和 key:value 格式。

相比之前提升

过去同一集使用多个模型时，通常人工汇总任务 ID、重试次数和价格；现在平台能够承担部分跨模型成本对账。

对 AI 短剧制作的具体价值

可计算每集消耗、草稿与正式成片成本，并定位重试过多的镜头。对小型创作团队，真实的 cost_per_approved_shot 比标价更有价值。

当前可用性／成本／限制

已通过 Runway Dev API 开放。标签不降低模型费率；用量数据按小时更新，不能认为实时；同一请求可进入多个普通标签分组，不要直接相加。标签对工作区可见，不可包含个人信息或密钥。

是否值得立即测试

强烈建议立即测试。为三条镜头加集数和阶段标签，生成后核对 Usage 报告、任务 ID、重试次数和实际费用。

原始来源： Runway API 更新 Request Tags 官方指南
02 · 重大更新

HeyGen Avatar 6：双人同框与局部改词

2026-11-17 技术报告 · 优先级 ★★★★★
发生了什么

HeyGen 的 Avatar 6 技术报告不仅展示 2K、语义手势，还展示约两分钟双人同框播客，以及仅替换视频中一个词语并尽量保留其余画面与声音的编辑能力。

核心技术变化

双人对话需要把各自声音与面部动作正确绑定，不能让听众跟着说话。局部改词需更新指定时间段的声音和口型，同时保护其他画面。

相比之前提升

相比先分别生成 A、B 两人再剪正反打，双人同框简化部分流程；改一句词也不必默认重生成整镜头。HeyGen 厂商测试中未修改区域 PSNR 为 48.3 dB，高于其比较方法，但这不是所有场景的独立保证。

对 AI 短剧制作的具体价值

适合双 AI 人物辩论、悬疑审问、访谈和连续对话。已完成剪辑却发现一句台词错误时，可以测试仅修改那句。

当前可用性／成本／限制

Avatar 6 已提供平台及 API。双人模式和局部改词具体入口、Credits 与权限要按账户核实。无固定时长上限不等于任意长片都稳定。真人身份及声音需本人明确授权，复杂全身交互仍待独立测试。

是否值得立即测试

值得立即测试。让男主说“我有三个证据”、女主先倾听再反问，之后把其中一句替换为新台词，检查角色身份、声音、口型、背景是否保持。

原始来源： HeyGen 技术报告 Avatar 6 产品页
03 · 重大更新

Hailuo 3.0 统一接入 Runway Dev API

2026-11-11 接入，技术复盘 · 优先级 ★★★★★
发生了什么

Runway Dev 在 11 月 11 日接入 MiniMax Hailuo 3.0，模型 ID 为 hailuo3，支持文生、图生和视频参考模式，以及关键帧、图像、参考视频和音频输入，输出五至十五秒的 768p 或 2K 视频。

核心技术变化

统一参考图、已有视频动作和声音信息，为视频生成建立比单纯 Prompt 更明确的约束。

相比之前提升

相比仅通过文字指定人物与动作，参考素材有望改善人物外貌和运镜遵循；统一平台调用也减少多模型接入所需的 SDK、任务和费用处理工作。

对 AI 短剧制作的具体价值

可制作开门、进入办公室、人物表情与简短对话等五秒至十五秒镜头，并对比不同参考方式的身份和空间连续性。

当前可用性／成本／限制

Runway 公开费率：768p 每秒 10 Credits、2K 每秒 15 Credits，参考图每张加 2 Credits，参考视频另按时长收费。按每 Credit $0.01，五秒 768p 约 $0.50、2K 约 $0.75，不包括附加输入费；支持参考不保证动作绝对一致。

是否值得立即测试

建议。用相同人物参考和五秒推门脚本，比较只有参考图与加入运动参考视频的结果，查看机位、门、手部和人物身份。

04 · 值得测试的新技术

Gemini Omni 1.2 Flash：十五秒音画生成与继续编辑

2026-11-05 原始发布，技术复盘 · 优先级 ★★★★★
发生了什么

Google 在 11 月 5 日发布 Gemini Omni 1.2 Flash，提供原生十五秒音画视频、增强参考遵循及对话式编辑，已在 Gemini API 与企业服务中开放。

核心技术变化

文本、图片、视频和音频参考进入同一模型，成片后可继续通过多轮自然语言指令要求修改。

相比之前提升

官方称较 Omni 1.1 降价约 30%，720p 起价 $0.07/秒，片段最长十五秒。低价和更长片段适合试镜头，但不能证明跨场景人物永不漂移。

对 AI 短剧制作的具体价值

用于室内对白、人物反应和独立短镜头，重点记录第一次生成通过率以及后续编辑成功率，避免只评价画质。

当前可用性／成本／限制

服务已开放，但地区、账号额度和能力可能不同。基础价格下十五秒 720p 理论起价 $1.05；其他规格、输入与后处理可能提高费用。真实人物和声音需要授权。

是否值得立即测试

建议。先生成十秒办公室对白，再仅更换桌上道具，验收人物脸、音频、机位和背景是否被误改。

05 · 值得测试的新技术

synctoon：使用可编辑 CSV 驱动 2D 嘴型与动画

开源项目，原始发布日期未核实 · 优先级 ★★★★☆
发生了什么

synctoon 是 Python 2D cut-out 动画流水线，从剧本出发，由 Claude、Gemini 或本地 LLM 规划人物眼睛、手势、背景、缩放及头部角度，结合 ElevenLabs 配音和词级时间戳逐帧生成动画。

核心技术变化

每帧的动画资产由一行 CSV 表示，制作者可在渲染前后改表情和口型；FFmpeg 等工具负责视频与声音合成。

相比之前提升

普通 AI 视频的局部错误常要求重生成；修改逐帧数据后，可利用缓存重渲染特定帧而不必重新请求 LLM。

对 AI 短剧制作的具体价值

适合纸片人辩论、动漫感短剧、人物科普和固定角色连载，也提供一种可移植的数据化表演控制设计。

当前可用性／成本／限制

GitHub 项目 GPL-3.0，依赖 Python、FFmpeg、角色素材和可选语音或 LLM API。主要面向 2D，不等于逼真人物视频；默认音素工具偏英语，中文嘴型和分词需自行验证。商用应检查代码、素材和声音许可。

是否值得立即测试

推荐技术测试。制作十秒双人对白，只改第三秒口型，尝试重新渲染并确认其他动画状态不变。

原始来源： synctoon GitHub

Video-Coder：让 Agent 写代码完成 3D 动作预演

2026-11-06 论文 · 优先级 ★★★★★
发生了什么

论文 Video-Coder 训练编程 Agent 自动写代码构建动态三维场景并执行，先渲染 Draft Video，再作为下游视频模型的结构与运动条件。论文声明开放数据、模型与代码。

核心技术变化

将人物动作、几何布局和相机路径从自然语言变成可执行的程序，并结合运行反馈和生成视频质量对 Agent 进行训练。

相比之前提升

论文报告其测试中相较 MiniMax H3 在 PhyGenBench 提高约 7 分、VBench-2.0 提高约 24 分；这些数据属于特定研究评测，不能直接当作商业短剧成功率。

对 AI 短剧制作的具体价值

递信封、推门、移动座位及人物绕桌行走都需要明确 3D 约束。先使用低成本预演验证人物位置，可能减少正式视频的物理错误。

当前可用性／成本／限制

研究系统需要三维渲染、模型推理及下游视频生成资源。开放代码和权重仍需逐项确认许可，预演路径并不保证最终生成画面逐坐标遵循。

是否值得立即测试

建议先测试其核心方法。让现有 Coding Agent 用 Blender 或 Three.js 创建办公室简化预演，检查绕桌和相机移动后再生成正式镜头。

07 · 开源与论文

Mise-en-Video：3D 空间控制多镜头人物走位与摄影机

2026-10-19 论文 · 优先级 ★★★★★
发生了什么

Mise-en-Video 研究可控的多镜头视频生成，允许设计每个镜头的角色位置、道具布局、运动轨迹和相机参数，并提出约 16 万视频的层级多镜头数据集。

核心技术变化

把分层叙事注意力和 3D-aware 布局约束结合，既保存跨镜头共同实体，又控制每个镜头的空间布局。

相比之前提升

普通 Prompt 很容易把门窗、人物的左右和遮挡关系弄乱；三维约束提供更加准确的方向和运动路径表达。

对 AI 短剧制作的具体价值

适用于正反打、多人对峙、办公室空间、追逐与道具交接。空间位置可提前规划，减少剪辑时出现不合理的走位。

当前可用性／成本／限制

学术研究并非可灵商业平台已直接开放同款三维控制 API 的证明。部署所需权重、成本和商业许可尚未核验。16 万是研究数据规模，不是普通创作者的素材要求。

是否值得立即测试

建议先用简单立方体搭建办公室和角色位置，给三条 ShotSpec 写机位、路径和视线约束，检查剪辑轴线。

原始来源： Mise-en-Video 论文
08 · 开源与论文

MSEditor：跨多个镜头一致地修改同一角色外观

2026-08-18 论文 · 优先级 ★★★★★
发生了什么

MSEditor 提出针对多镜头一致性编辑的框架，处理人物在不同景别、姿势、机位和遮挡下因编辑出现的外观漂移。

核心技术变化

利用 Supervisory Adapter 注入跨镜头信息，并使用 Cross-Shot Packing 合并语义相关镜头的注意力上下文，降低累积不一致。

相比之前提升

普通 video-to-video 每次只修改一个镜头，很容易把原本同一件外套改成三种不同款式；跨镜头统一约束更贴近真实电视剧制作需求。

对 AI 短剧制作的具体价值

适合整集替换人物服装、发色、道具或场景风格。应以“一个实体、多条镜头、同一次修改要求”的方式组织镜头数据。

当前可用性／成本／限制

论文公开，但商业 API、完整权重及统一报价尚未核实；强遮挡与复杂光照仍可能导致失真，不可承诺零漂移。

是否值得立即测试

建议设计三镜头对照，把角色的蓝色外套一致改为红色，验收色彩、款式和脸部身份。

10 · 生产实践

ElevenAgents 11 月 19 日模型退役与角色回归

2026-11-19 模型迁移节点 · 优先级 ★★★★★
发生了什么

ElevenLabs 11 月 17 日说明 gemini-3.6-flash 已逐步回退至 gemini-3.8-flash，并于 11 月 19 日进入原模型退役节点；多个老 GPT 模型亦列有未来迁移安排。

核心技术变化

变化发生在互动角色的语言模型层，即使角色 Prompt、声音或工具没有变化，底层模型调整也可能影响回复内容、工具调用与叙事选择。

相比之前提升

新模型可能改善速度与能力，但不能默认角色性格、剧情信息披露、耗时或费用不变；必须使用稳定评测集进行回归。

对 AI 短剧制作的具体价值

互动侦探、虚拟 NPC 或辩论角色不能突然泄露剧情、改变人物设定或错误更新道具归属，迁移测试是短剧生产可靠性的组成部分。

当前可用性／成本／限制

官方迁移策略已公布，替代模型的价格、延迟和行为以账户当前配置为准；单条测试通过并不代表完整剧情安全。

是否值得立即测试

建议准备十条标准剧情问题，覆盖已知线索、禁止剧透、角色身份、道具状态和工具调用，比较更新后的回答与费用。

原始来源： ElevenLabs 官方变更记录

今天最值得测试的 3 个技术 / 工具

1. HeyGen Avatar 6：双人对话与局部改词

先检查男主说话时女主能否保持倾听，再仅修改一句错误台词，检查改词以外的人脸、口型、声音及背景是否保持。适合固定人物的辩论、访谈和悬疑短剧。

2. Video-Coder + 三维预演

让 Coding Agent 在 Blender 或 Three.js 中创建“人物绕过桌子走到门口”的简化空间预演，检查门、桌子、相机和运动路线，验收后再用于视频生成。

3. Runway Request Tags：成本报表

给每次生成加 episode、shot、stage 标签，记录任务 ID、重试次数与最终验收结果。第一次算出实际每个合格镜头的成本。

对 AI 短剧生产流程的影响判断

推荐生产链路

StoryBible / Character Registry → 3D Staging / ShotSpec → Draft Video / Model Router → Video / Avatar / Audio → Cross-shot Edit / Lip Sync → Quality Gate / Regression → Cost Tags / Timeline / Archive

判断 1：双人数字人需要把说话者、听众、交替发言和情绪反应分开控制，不是只让一个人物嘴部动起来。

判断 2：Video-Coder 和 Mise-en-Video 表明可验证三维预演是从模糊文字走向精确走位控制的重要中间产物。

判断 3：跨镜头编辑需要统一实体参考：一次修改同一角色的外套、发型或道具，应让相关镜头共享同一约束，而非三次随机编辑。

判断 4：成本归因要关联集数、镜头、阶段、模型、任务 ID、重试和验收状态，才能计算 cost_per_approved_shot。

判断 5：模型迁移也会破坏角色连续性：互动短剧的 LLM、声音引擎和工具定义都应版本化，并通过标准剧情回归测试。

长期指标：character_identity_pass、speaker_lip_sync_pass、spatial_continuity_pass、cross_shot_edit_pass、model_regression_pass、retry_count、cost_per_approved_shot、manual_repair_minutes。

今日小练习｜25 分钟

主题：设计 15 秒双人悬疑短剧的空间预演、双人表演和成本归因。

练习目标：将人物走位、说话人、镜头状态及费用表达为可检验的数据，而不是只写一段自然语言 Prompt。

准备材料与工具：文本编辑器或 Excel、两名原创虚构人物、一个办公室背景、桌子、信封；可选 Blender、Three.js、HeyGen Avatar 6 和 Runway Dev，无模型额度可先完成纸面方案。

0—4 分钟 · 建立角色与场景状态
定义 CHAR_A、CHAR_B、LOC_OFFICE、PROP_LETTER，记录人物外貌、声音、站位及桌子、门、信封的起始位置。
4—8 分钟 · 规划三个五秒镜头
S01 女主拿起信封；S02 男主从门口进来；S03 对峙，男主说“我有三个证据”，女主先沉默。明确镜头可见人物、首尾状态和机位。
8—12 分钟 · 制作简化空间预演
用方框、平面草图或 Blender、Three.js 物体表示人物家具，画出人物和摄像机路径，检查不能穿桌、开门方向和轴线。
12—16 分钟 · 制定说话人和口型规则
记录 speaker_id、visible_characters、audio_start、audio_end；S03 男主说话仅男主同步嘴型，女主倾听；对“三个证据”添加计数手势条件。
16—21 分钟 · 设计生成任务成本标签
使用 episode:demo01、shot:s01/s02/s03、stage:draft/final，记录实际模型、task_id、费用、重试次数；无真实生成一律标 NOT_TESTED。
21—25 分钟 · 验收及局部返工
检查人脸身份、空间位置、信封、手势、嘴型、背景和费用，失败时记录 shot_id、timecode、repair_target，不重做已合格的部分。

验收标准：两份角色卡、一个办公室空间布局、三条 ShotSpec、一份说话人和口型时间表、一份成本标签任务记录模板及至少八项质量检查。所有未实际生成的项目不得标记 PASS，统一写 NOT_TESTED。

思考题：为什么双人同框嘴型比单人难？三维预演正确是否保证最终视频正确？三次生成才通过的镜头成本如何分摊？整集角色外套改色为何不适合逐镜头独立生成？

扩展到真实短剧流程：将三镜头扩展为十镜头、六十秒短剧。Agent 读取剧本和角色库，生成空间预演，制作多个模型的候选；质检 Agent 评估人物、物理和声音一致性，人工批准后剪辑并归集成本。积累十集后对比各模型真实生产效率。

本期结论

应该投入可控人物和机位、定向修复、真实成本归因及升级后仍可复现的工作流，而不只是随机尝试更多 Prompt。
