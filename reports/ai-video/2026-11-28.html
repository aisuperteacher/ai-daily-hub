一、重大更新

01｜MAGI-2：480B 有声视频旗舰进入更多 API 渠道

11 月 24 日原始发布，11 月 27 日 Runware 接入｜优先级：高

发生了什么：Sand AI 正式版 MAGI-2 已接入 Runware（sandai:magi@2），支持 4—30 秒、1080p 有声视频，含文生视频、首尾帧和多模态参考模式。

核心技术变化：单流 Transformer 共同处理音频、视频和文字，采用 Multi-Head Latent MoE；正式版总参数 480B、约 28B 活跃参数，预训练规模约 4T tokens。支持时间线控制，最多 10 张图、5 段视频及 5 段音频参考。

相比之前提升：8 月 Preview 约 114B 总参数、6B 活跃参数；厂商公布 Artificial Analysis 四项平均 Elo 从 998.5 升至 1150.3（+151.8）。这是指定评测结果，不是短剧成片通过率。

短剧制作价值：可一次规划一段 15—30 秒的对话与连续事件，把人物、道具、动作和声音参考放入同一任务，减少拼接次数；尤其值得验证说话人、听众反应与切镜时刻。

可用性／成本／限制：Sand 官方 API 标价 $0.08/秒，15 秒 $1.20、30 秒 $2.40，不含返工和其他服务费用。官方价格页称暂不支持充值，需确认账号权限；Runware 另行计价，其首尾帧与多参考模式不能混用。官方称完整版权重后续开放，不能视为已开放；高速动作和复杂声音仍可能出错。原生输出 25fps，第三方实际封装以文件为准。

是否值得立即测试：是。选一个 15 秒三镜头双人悬疑场景，与现有模型对照角色身份、台词归属、切镜与实际费用。

来源：https://sand.ai/blog/magi-2/ · https://platform.sand.ai/docs/model-pricing/ · https://runware.ai/docs/models/sandai-magi-2

02｜FLUX 3 Video：720p 草稿通过后可用缓存完成 4K 输出

11 月 27 日 Runware 更新｜优先级：高

发生了什么：Runware 的 FLUX 3 Video 增加 2K、4K 和 9:21 画幅支持，草稿缓存回放也支持指定更高输出规格。

核心技术变化：先以 720p 生成草稿，再用 inputs.draftCache 提交高规格回放；不必把已选草稿当作全新随机生成任务。长提示词上限 32,000 字符。

相比之前提升：此前接口主要提供 720p、1080p；现在可将同一草稿推进到 4K。实际是否保持动作和细节仍须比较，不能宣称逐像素一致。

短剧制作价值：先验收故事、表演与构图，再为入选镜头制作母版，避免把预算花在明显失败的高分辨率候选上。

可用性／成本／限制：API 已开放；宽高需符合 32 像素对齐，16:9 的 4K 示例为 3840×2176，而非 3840×2160；9:21 的 4K 为 1856×4352。草稿固定 720p；回放缓存的有效期、具体费用与差异需实测，最终交付可能要裁切或缩放。

是否值得立即测试：是。对同一个批准的 720p 草稿回放到 4K，比较首中尾帧、人物动作、画幅和费用，不仅检查清晰度。

来源：https://runware.ai/docs/changelog · https://runware.ai/docs/models/bfl-flux-3-video

二、值得测试的新技术

03｜Ming-Image-0.2-Design：开源分镜与海报设计模型

11 月 25 日模型卡评测日期，26 日发布报道｜优先级：中高

发生了什么：蚂蚁 inclusionAI 开放 Ming-Image-0.2-Design 权重和推理代码，模型 DiT 为 6B 参数，MIT 许可。

核心技术变化：加强复杂构图、光照和文字排版，可用于空间视觉设计；支持透明背景图像输出。

相比之前提升：官方模型卡称截至 11 月 25 日在 Artificial Analysis 总体文生图榜单中位居开放权重模型第一（初步结果），此前 0.1 主要在 UI/UX 设计类别领先。不是人物视频一致性评测。

短剧制作价值：适合制作分镜草图、人物关系卡、道具设计、片头封面和空间参考；透明素材可用于程序化合成。

可用性／成本／限制：权重可下载；推荐默认 2048×2048，官方验证配置为单张至少 80 GiB 显存 CUDA GPU。没有统一 API 费率；本地运行有硬件成本。更细的人物部件分层是单独模型方向，本次不把它视为已随权重交付。

是否值得立即测试：有算力则测试同一剧集的三张统一风格封面，核查文字、构图和人物特征；普通电脑先看样例与模型卡。

来源：https://huggingface.co/inclusionAI/Ming-Image-0.2-Design · https://github.com/inclusionAI/Ming-Image

04｜NVIDIA Cosmos 3 Nano：12GB 显存也有机会运行视频世界模型

11 月 24 日官方部署指南｜优先级：中高

发生了什么：NVIDIA 发布使用 Hugging Face Diffusers 和 CPU offloading 在消费级 GPU 上运行 Cosmos 3 Nano 的指南。

核心技术变化：将大部分权重放在系统内存，需要时搬到 GPU，另提供 FP8 混合精度方案。支持多种输入和控制方式，包括文生、图生、视频编辑及动作控制。

相比之前提升：显存门槛可以降至 12GB 级，而不是把全部权重长期放在 GPU；代价是内存与 PCIe 数据传输以及更长等待时间。

短剧制作价值：适合研究空间预演、道具物理和镜头控制，或搭建私有测试环境，不必将所有原始素材交给云服务。

可用性／成本／限制：官方测试使用 Linux、Python 3.12、CUDA PyTorch，消费级 GPU 主机约 128GB RAM，并非已证明的最低内存。RTX 5070 的 720p 文生视频 BF16 示例约 2624.9 秒（近 44 分钟），峰值 9.94 GiB；不是实时视频模型。Windows 原生兼容性、本地电费及商业许可需另查。

是否值得立即测试：技术团队可做部署评估；创作团队不要为了本地化立即购置硬件。先核查显存、内存与单条任务时间预算。

来源：https://developer.nvidia.com/blog/how-to-run-nvidia-cosmos-3-on-local-ai-devices-using-hugging-face-diffusers · https://github.com/NVIDIA/cosmos-framework

三、开源与论文

05｜MEMO：每一帧都可以重建完整动态场景的三维网格

11 月 25 日提交，26 日收录｜优先级：高

发生了什么：论文 A Mesh for Every Moment 提出从多台同步摄影机采集的动态场景中恢复每帧三维网格。

核心技术变化：用随时间变化的高斯核描述每个 Gaussian 的位置和旋转，利用点轨迹初始化运动，在动态几何场中提取任意时刻的网格。

相比之前提升：不只重建外观或单独前景物体；作者在包含 9 个动画场景的 Blender-Moments 与两个真实数据集上报告几何重建优于比较方法。

短剧制作价值：可研究一次拍摄后重建人物与环境、选择其他机位、处理道具遮挡，以及将真实动作转为可编辑三维资产。

可用性／成本／限制：研究预印本，需多机位同步采集；本次未确认完整可部署代码、运行成本或商业许可。不是从单张图生成任意完整三维表演的工具。

是否值得立即测试：先用已有多机位素材设计同步时间码、场景标定和网格验收规则，研究团队再评估复现。

来源：https://arxiv.org/abs/2611.34939 · https://memo-4d.github.io/

06｜AgenTAP：物体被遮挡再出现，Agent 如何确认还是同一个点？

11 月 25 日提交，26 日收录｜优先级：高

发生了什么：Tracking Any Point with Agentic Visual Reasoning 提出用视觉语言 Agent 追踪视频中具体物理表面点，并判断其可见性。

核心技术变化：Agent 主动选择观察帧，复核自己的坐标与身份预测，把消失后再出现的点轨迹重新连接；研究据此建立 EgoTAP-4D 数据集。

相比之前提升：作者报告以 GPT-6 Astra 为基础时，在点定位和可见性判断上超过其比较的专用视觉模型，无需针对点对应关系微调；不是所有视频跟踪场景的通用结论。

短剧制作价值：用于检查道具是否在遮挡后保持连续、特效贴附位置、衣服徽章及镜头内运动轨迹；有助于从整张画面主观评分转向可定位的错误证据。

可用性／成本／限制：论文与项目页公开，尚未核实完整可部署实现及推理成本；多轮视觉检查可能较慢。点追踪不等于人脸身份认证，复杂遮挡仍需人工复查。

是否值得立即测试：用一段原创素材标记信封一角，在被手遮挡前后检查坐标和可见状态。可先人工记录，再考虑自动跟踪。

来源：https://arxiv.org/abs/2611.34943 · https://agentap.cs.virginia.edu/

07｜AURA：音频驱动的流式数字人，减少等待后续台词的延迟

11 月 19 日论文；本期补充研究｜优先级：高

发生了什么：AURA 研究公开 1.3B 与 5B 流式音频驱动数字人模型权重，并提供 3 万条合成视频及教师轨迹数据。

核心技术变化：按小块生成视频，滚动维护 KV Cache，仅需当前音频块即可开始推理，结合两阶段蒸馏降低计算量。

相比之前提升：论文报告 1.3B 版本在单 GPU 上为 576p、20.7fps 生成速度（播放速率 16Hz），比自身双向教师快 23 倍；5B 版本 720p、9.7fps，快 17 倍。均为作者测试条件下的结果。

短剧制作价值：适合探索实时双人辩论、虚拟主持、互动角色与直播式故事，不必等整段语音生成完才启动表演。

可用性／成本／限制：论文说明权重发布，具体硬件、许可证、中文嘴型与多角色同框能力需独立核实；5B 的 9.7fps 不足以直接满足常见实时播放需求，模型速度也不含全链路延迟。

是否值得立即测试：有合适 GPU 的团队可记录首帧延迟、持续帧率、音画偏差及身份漂移；普通创作者先使用现有离线数字人服务。

来源：https://arxiv.org/abs/2611.26540

四、生产实践

08｜Eleven v4 单请求扩大到 100,000 字符：长旁白仍应分段管理

11 月 23 日官方 API 更新｜优先级：中高

发生了什么：ElevenLabs 将 Eleven v4 和 v4 Turbo 的每次 TTS 字符上限由 10,000 提升到 100,000，官方估算约 100 分钟音频。

核心技术变化：接口容许更长文本，减少因硬限制切分的次数；这不是新声音克隆模型，也不代表长时情绪一定稳定。

相比之前提升：单请求容量增加十倍；对于长旁白、剧情回顾和多集有声稿可以减少任务管理开销。

短剧制作价值：可将整集旁白作为统一音频任务；对白仍建议按角色和剧情段分开，以方便定向修改、口型同步与字幕对齐。

可用性／成本／限制：官方 API 已更新，费用按套餐和字符使用量确认。100,000 字符不保证中文恰好 100 分钟；长任务失败的返工成本更大，不能默认改一词就重做整集。

是否值得立即测试：用同一授权声线生成一段完整旁白及分段版本，对照语气、停顿、时长、修改成本与声线一致性。

来源：https://elevenlabs.io/docs/changelog/2026/11/23

09｜Sand AI 任务管理：视频生成请求超时后不要盲目重发

11 月 24 日旗舰上线后的官方 API 生产实践｜优先级：高

发生了什么：Sand 官方 API 文档公开默认组织级 20 次/分钟创建任务、20 次/分钟读取任务、5 个生成并发，以及请求重试规则。本项为当前文档核查，不声称 27 日才更新。

核心技术变化：创建与轮询配额分开，生成任务异步执行；创建请求不保证幂等。若客户端超时或丢失响应，后台仍可能已经接受任务。

相比之前提升：从简单同步调用转向有任务 ID、限流和状态机的生产设计；官方建议单任务每 10 秒轮询，多任务错峰。客户端轮询超时并不会取消生成。

短剧制作价值：批量生产时可以避免重复提交同一镜头、重复扣费、任务状态丢失。一个已获任务 ID 的镜头应先恢复查询，而非重新生成。

可用性／成本／限制：默认配额可能按组织调整。读取遇到网络错误、429、500 或 503 可有限退避重试；创建响应不明且没有 ID 时应进入待核对状态，不能假设服务端支持幂等键。重试可能产生费用。

是否值得立即测试：模拟创建响应丢失，验证系统是否保留业务镜头 ID、请求记录、任务 ID，并且阻止自动重复创建；无需付费即可用模拟服务练习。

来源：https://platform.sand.ai/docs/limits/ · https://platform.sand.ai/docs/api-reference

今天最值得测试的 3 个技术／工具

1. MAGI-2：用 15 秒双人悬疑镜头检验多参考、声音和叙事连续性；原厂标价单次 $1.20，先设预算再调用。

2. FLUX 3 Video 草稿缓存：先在 720p 选镜头，再回放 4K，验证构图与动作是否保留以及规格兼容性。

3. AgenTAP 式点轨迹质检：先人工标注遮挡前后道具角点与可见状态，再让有能力的视觉 Agent 复核；无需先部署论文系统。

对 AI 短剧生产流程的影响判断

角色与场景资产 → 带时间和说话人约束的分镜 → 草稿生成 → 物理点与音画检查 → 批准镜头 → 高清回放或局部修复 → 交付与成本归档。

第一，长有声视频值得测试，但不能用 30 秒长度替代跨镜头质量指标；应检验身份、道具、台词归属、切镜和声音触发。第二，草稿与母版分层，批准的草稿应保存缓存、模型版本与参考素材。第三，空间及道具质检需要明确的时间、坐标与可见性证据，而不只是整条视频评分。第四，低显存可运行不代表低延迟或低成本；本地部署应比较每条合格镜头的总时间。第五，异步任务必须保存状态并区分安全的读取重试与可能重复扣费的创建操作。建议记录 character_identity_pass、speaker_lip_sync_pass、prop_track_pass、cut_time_error_ms、draft_replay_pass、cost_per_approved_shot、duplicate_task_count、manual_repair_minutes。

今日小练习｜25 分钟

主题：一封信的三镜头悬疑短剧——从草稿到母版，且不重复提交任务。

目标：学会用时间线、道具轨迹、缓存和任务状态建立可验收的 15 秒短剧生产方案。

材料／工具：文本编辑器或表格；两个原创虚构角色、办公室与信封参考、可选 MAGI-2、FLUX 3 Video 和现有剪辑工具；没有额度可用已有授权视频或纸面模拟。真实人脸与声音必须获得授权。

步骤：0—4 分钟，定义角色 A/B、信封 PROP_01、场景 LOC_01 及固定服装。4—8 分钟，规划 S01（0—5 秒，A 拿信）、S02（5—10 秒，B 接信，手短暂遮挡信封）、S03（10—15 秒，A 说“你早就知道了？”，B 沉默）；为每镜头写预期说话人和可见道具。8—12 分钟，选信封角点，记录遮挡前、遮挡中、再出现的时间及可见性。12—16 分钟，规划 MAGI-2 候选及 FLUX 草稿、缓存和 4K 回放；有额度时提交一条测试任务，否则只设计。16—21 分钟，模拟创建超时、任务 ID 已知与未知两种情况；前者恢复查询，后者标记待核对，不自动重发。21—25 分钟，填写质量表、费用及返工目标；有实际视频则检查首中尾帧、声音和时间线。

验收标准：两份角色卡、三条 ShotSpec、至少三条道具追踪记录、草稿与母版版本关联、一次超时状态模拟、八项质量检查。只在实际观察后标记 PASS/FAIL，否则 NOT_TESTED。自定切镜误差阈值 0.3 秒，不是论文标准。

思考题：为什么 30 秒生成能力不能保证剧情正确？如果草稿回放改变了人物表情，应重新批准吗？为什么创建超时可能产生两次扣费？信封被挡住时为什么不能凭猜测填写可见坐标？

真实流程扩展：扩展到十个镜头、60 秒短剧；制作 Agent 读取人物资产和 ShotSpec，提交任务并保存 ID，质检 Agent 记录点轨迹、身份和音画问题，人工批准后才升级母版。积累每集费用、重试和返工数据，比较不同模型的实际生产效率。

本期结论：优先建设可复用的草稿、可定位的质量证据和可恢复的任务状态，而不是每遇到错误就重新生成整段视频。
