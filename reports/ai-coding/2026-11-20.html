2.1 Auto Mode 扩展到 Bedrock、Google Agent Platform、Foundry 和 Gateway

版本与发布日期：2.1.328 · 2026-11-19 01:14 UTC / 北京时间 09:14 · 官方依据

变化内容：为 Opus 4.6、Sonnet 4.6 在 Amazon Bedrock、Google Cloud Agent Platform、Microsoft Foundry、Claude Apps Gateway 增加 Auto Mode。适用的交互 Session 未显式指定权限模式时会自动启动 Auto Mode；修复第三方 Gateway 禁用 Experimental Betas 时 Auto Mode 每轮失败。

技术意义：Auto Mode 是操作风险评估，而非模型推理能力。默认权限路径变化可能让相同任务采取不同的 Allow/Ask/Deny 行为。

分场景影响、Breaking-risk 与检查建议

受影响场景严重度方向明确行动Breaking-risk
第三方 Gateway、Bedrock/Foundry、企业 AgentHigh安全治理利好 + 默认行为风险Test before upgradingHigh（依赖旧审批方式）
Windows PowerShell、CI/Headless、无人值守脚本High（适用相关 Provider/Auto Mode 时）兼容风险Change config / Test before upgradingMedium–High

第三方 Gateway、Bedrock/Foundry、企业 Agent 的验证方式：核对真实 Permission Mode、Tool Allow/Ask/Deny、分类服务可达性。模型请求成功不代表审查成功。

Windows PowerShell、CI/Headless、无人值守脚本 的验证方式：明确配置预期权限模式，不把交互式默认值直接推广到 Headless。

谁可忽略：不使用相关 Provider、模型或 Auto Mode 组合的用户。

2.2 mcp_tool Hooks 支持 onFailure: "block"

版本与发布日期：2.1.328 · 2026-11-19 01:14 UTC · 官方依据

变化内容：mcp_tool Hook 新增 "onFailure": "block"，与 Command/HTTP Hook 的失败阻断策略对应。

技术意义：Hook 执行失败不等于审查成功。Fail-closed 可在审查 MCP 服务不可用时停止受保护的副作用操作。

分场景影响、Breaking-risk 与检查建议

受影响场景严重度方向明确行动Breaking-risk
企业安全 Hooks、Remote MCP、删除/部署操作High安全利好 + 可用性风险Test before adopting / Change configHigh（启用阻断策略）
普通 MCP Tool Call、不使用 HookLow中性No actionLow

企业安全 Hooks、Remote MCP、删除/部署操作 的验证方式：用测试 MCP 模拟连接拒绝、超时、服务端错误、正常允许，确认操作是否真正被阻止，并准备恢复流程。

普通 MCP Tool Call、不使用 Hook 的验证方式：无需变更。

谁可忽略：未使用 mcp_tool Hooks 的用户。

2.3 Headless Resume 可限制延迟的 Tool Call

版本与发布日期：2.1.328 · 2026-11-19 01:14 UTC · 官方依据

变化内容：新增 CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME，允许宿主阻止 claude -p --resume 或 --continue 继续执行被 Hook 延迟的 Tool Call。

技术意义：Session Resume 可能跨工作目录、进程、宿主或认证上下文；历史 Pending Tool 不等于当前环境下已获授权。

分场景影响、Breaking-risk 与检查建议

受影响场景严重度方向明确行动Breaking-risk
CI/Headless、SDK Host、无人值守恢复High执行安全利好Test before upgrading / Change configMedium–High
纯交互 Session、未使用 Deferred HooksLow中性No actionLow

CI/Headless、SDK Host、无人值守恢复 的验证方式：测试恢复前后工作目录、Gateway 身份、权限、Pending Tool 和故障状态；先在测试任务验证环境开关。

纯交互 Session、未使用 Deferred Hooks 的验证方式：无需专项回归。

谁可忽略：不使用 claude -p --resume、--continue 或 Deferred Tools 的用户。

2.4 Scheduled Tasks 文件保护与 /tasks 入口

版本与发布日期：2.1.328 + 2.1.329 · 2026-11-19 / 北京时间 11-20 06:14 · 官方依据

变化内容：项目 Scheduled Tasks 文件无法读取或包含错误配置时，保存其它任务不会再意外删除原任务；/tasks 可展示本 Session 的 Scheduled Tasks、/loop 唤醒、Goal、Conversation Fork，并提供停止入口。

技术意义：配置读取失败不能解释为没有任务；保存操作要保护历史持久数据。

只手动启动 Claude CLI 的验证方式：不涉及内置调度。

谁可忽略：不使用 Claude Code 内置调度的用户；不应据此推断 ChatGPT 定时任务变化。

2.5 第三方 Provider 中 MCP JSON Schema 联合类型修复

版本与发布日期：2.1.328 · 2026-11-19 01:14 UTC · 官方依据

变化内容：根级 anyOf、oneOf、allOf Input Schema 的 MCP Tools 在第三方 Provider 或关闭 Telemetry/Flags 时不再错误消失；无效 Schema 现在跳过对应 Tool 并告知 Claude，而不是拖垮整个请求。

技术意义：Tool Discovery、Schema 解析与服务端验证不同；工具不可见可能来自解析兼容问题而非权限不足。

简单对象入参的内置工具 的验证方式：无需额外调整。

谁可忽略：不使用自建 MCP 或复杂联合 Schema 的用户。

2.6 MCP OAuth、后台重连与卸载 Plugin MCP 的生命周期修复

版本与发布日期：2.1.329 · 2026-11-19 22:14 UTC / 北京时间 11-20 06:14 · 官方依据

变化内容：清除 MCP 认证时后台 Token Refresh 不再把注销状态恢复；慢速重连、旧协议 HTTP MCP 的后台任务获得修复；移除的插件 MCP Server 在 Headless reload_plugins 后不再错误保持连接；/mcp 展示远端 JSON-RPC 连接失败消息。

技术意义：认证状态、协议、Tool Discovery 与 Plugin 生命周期必须一致；迟到的异步结果不能覆盖最新登出/卸载决定。

版本与发布日期：2.1.329 · 2026-11-19 22:14 UTC · 官方依据

变化内容：Code Mode 现在可与 OpenTelemetry Events/Metrics 同时启用，每次脚本中的工具调用产生对应事件；Tracing 仍不兼容 Code Mode。修复 Code Mode 无界循环、读取大文件、背景 Subagent 唤醒、取消等导致的内存持续保留。

技术意义：Events/Metrics 可用不代表完整分布式 Tracing 可用；CLI 内存保护也不能代替业务级资源配额。

2.8 Code Mode 长 MCP Task、审批等待与 Tool Result 状态

版本与发布日期：2.1.328 / 2.1.329 · 2026-11-19 · 官方依据

变化内容：修复等待权限批准、MCP Form/Link、长时 MCP Call 时计时错误。部分超过两分钟的 MCP Calls 曾把 moved-to-background 提示误当 Tool Result；现在等待最多约十分钟，之后明确失败。修复 Resume 的 Skill/Hook Context、中途新连接 MCP、无参数 Tool、超过 4,096 Tools、只读 Subagent 错误显示写工具等。

技术意义：MCP 调用启动、Waiting、Completion 和 Failure 是不同状态；中途通知不能直接等同业务成功。

Skills/Mods/Tool Search 开发Medium–HighTool API 可靠性利好Test before upgradingMedium

Skills/Mods/Tool Search 开发 的验证方式：覆盖大量工具、复杂 Skill、Tool 权限、实际结果。

谁可忽略：只使用快速内置 Tool Calls 的用户。
