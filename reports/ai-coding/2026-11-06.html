Codex CLI 0.167.0：Agent 命令中心、跨后端会话、系统代理实验开关

日期：2026-11-06 01:40 UTC　版本：rust-v0.167.0 · 正式版　行动：Test before upgrading

官方原文：https://github.com/openai/codex/releases/tag/rust-v0.167.0

① 官方事实、版本与出处

2026-11-06 01:40 UTC

② 核心变化与技术机制

新增 codex agents --no-daemon 进入 Agent 命令中心；跨已连接后端切换会话并保留草稿；支持在支持的终端预览本地图像；提供 Google Cloud Vertex AI 配置向导 gcp_setup_wizard；可通过 /experimental 试用 Windows/macOS 系统代理。修复切换模型提供商后对话可读性、网络审批竞争以及自动上下文压缩对异常 usage 数据的估算。

③ 实际价值

此前在跨模型提供商、代理和长对话下容易出现会话恢复或成本判断上的不确定性。此次提高运行管理、会话延续和故障复核效率；这是正式版变更，但并非新模型能力或新的 API 计费承诺。

④ 受影响业务与工程场景

Windows + Proxifier/v2rayN 或系统代理、第三方 Base URL、多后端切换和多个并行 Agent 任务。企业 Gateway 应检测连接路径与授权边界，不因启用系统代理开关就推断所有流量已正确绕行。

⑤ 风险等级与行动

Medium · 利好与兼容风险并存

⑥ Breaking-risk/兼容性

Release Notes 未宣称强制 Breaking Change。实验性系统代理的路由、证书信任和直连/代理差异必须在测试环境验证；跨后端聊天无法恢复时现在可读取历史并生成新的可编辑提示词，仍不等同于无损恢复原上下文。

⑦ 回归步骤与谁可忽略

先记录 codex --version 与当前 config.toml；升级后运行 codex --version、codex agents --no-daemon；在 /experimental 中按需测试系统代理；用一条未涉及生产凭据的会话测试 provider 切换、恢复、网络审批和 compaction；检查 Gateway 请求日志和实际出口 IP。

谁可以暂缓

没有使用 Codex CLI、Windows 系统代理或跨 provider 会话的人可以仅关注。

Cursor：Build Live Apps in Cursor

日期：2026-11-05　版本：官方产品更新 · 未提供统一 CLI 版本号　行动：Test before enabling in organization

官方原文：https://cursor.com/changelog

① 官方事实、版本与出处

2026-11-05

② 核心变化与技术机制

Cloud Agent 可以按自然语言要求构建并发布在线应用，流程可包含应用脚手架、Postgres、Cursor SSO 后的身份认证与托管；发布时选择域名并获得共享链接。产品公告称组织成员可通过更新 Cursor 试用。

③ 实际价值

缩短从内部工具想法到可访问应用的交付路径，尤其适合低风险原型和单人开发；官方尚未给出所有组织的具体价格、资源限额、安全认证与 SLA，不应据此推断生产可用性。

④ 受影响业务与工程场景

内部运维面板、运营工具和演示系统；若涉及公司业务数据、隐私、机密代码或外部网络资源，必须检查是否允许使用 Cursor 托管、SSO 策略、数据库驻留区域、日志和密钥治理。

⑤ 风险等级与行动

Medium/High · 发布与权限治理风险

⑥ Breaking-risk/兼容性

不是 CLI 破坏性升级；最大的风险在于生产数据越界与把实验应用误当有审批的正式系统。不要把凭据复制到提示词；所有外部系统连接必须通过专用密钥与权限审批。

⑦ 回归步骤与谁可忽略

在隔离组织/测试环境用无敏感数据的小工具验证：能否正确发布、限制组织可见性、撤销访问、删除数据库和项目、保留审计记录；检查权限最小化、成本、备份和退出机制。

谁可以暂缓

仅本地编码、不使用 Cursor Cloud Agent 或无法接受其托管模型的团队可以暂时忽略。

Gemini CLI 0.67.0 正式版与 0.68.0-preview.0

日期：2026-11-04　版本：Stable v0.67.0 / Preview v0.68.0-preview.0　行动：Upgrade stable; test preview separately

官方原文：https://github.com/google-gemini/gemini-cli/blob/main/docs/changelogs/latest.md · 关联官方更新

① 官方事实、版本与出处

2026-11-04

② 核心变化与技术机制

正式版引入 models 命令和 --list-models；通过 exec stdio 将 IDE companion 桥接至容器沙箱；改善取消和信号处理，避免非交互模式继续执行后续工具；修复只读文件/硬链接写入及工作区路径问题；MCP 权限请求呈现工具与服务器元数据。Preview 0.68 另改进扩展校验/安装和模型选择。

③ 实际价值

模型目录发现可减少无效 Model ID，取消执行的确定性和对 MCP 权限的显示直接影响自动化安全。Preview 的功能未必具备稳定版保障，不能混为当前正式版本。

④ 受影响业务与工程场景

CI/headless、IDE 容器化开发、MCP、多项目工作区；Windows npm 全局安装场景需关注 terminal unicode/路径和升级一致性。

⑤ 风险等级与行动

Medium · CLI/IDE 与安全行为变化

⑥ Breaking-risk/兼容性

官方没有把这次 stable 标为大范围 Breaking Change；但是新的文件安全行为可能拒绝以前能够写入的只读/链接路径，这是应当验证的安全收紧。Preview 存在回归风险。

⑦ 回归步骤与谁可忽略

npm install -g @google/gemini-cli；gemini --version；gemini models 或 gemini --list-models（按实际子命令帮助验证）；在测试仓库执行取消长工具任务，确保没有后续工具执行；对只读文件、符号链接和 MCP 权限弹窗做回归。

谁可以暂缓

不使用 Gemini CLI 或不接入 MCP/容器 IDE 的人可以先只记住稳定版本号。

Claude Code 2.1.318：凭据到期可观测性与设置写入修复

日期：2026-11-04　版本：v2.1.318 · 正式版；关联 2.1.317　行动：Upgrade after checking hooks and shared home

官方原文：https://github.com/anthropics/claude-code/releases/tag/v2.1.318 · 关联官方更新

① 官方事实、版本与出处

2026-11-04

② 核心变化与技术机制

增加 claude auth status 的 loginExpiresAt、非交互 JSON 的 credential_expires_at，临近到期时告警；修复 --continue 在错误工具调用重试耗尽后的历史会话丢失、共享网络目录配置保存误报成功、MCP 添加/删除时配置写入锁、插件验证/令牌刷新。2.1.317 为 Agent SDK Hook 加入 onFailure: block，支持失败时阻止动作，并添加计划任务 connector 变更告警。

③ 实际价值

对 Windows、企业网络共享 home 和 CI agent 而言，‘配置已写入’以及‘登录还有效’都是实际运行前置条件；修复减少静默失败，并为阻断型 Hook 提供明确策略。

④ 受影响业务与工程场景

PowerShell Hooks、CLAUDE.md/Skills/Plugins、MCP 管理、企业 SSO、持续集成和多终端共用配置。涉及 Hooks 或高风险工具时，需确认拒绝/失败是否被正确传导。

⑤ 风险等级与行动

Medium · 身份验证/配置竞态

⑥ Breaking-risk/兼容性

未见强制格式迁移；使用 onFailure: block 的扩展会把原来的软失败变为真正阻断，属于有意的策略变化。v2.1.316 还修复了 PowerShell 某些 Hook exit 2 未阻断的问题，升级后要重测。

⑦ 回归步骤与谁可忽略

claude --version；claude auth status；在测试环境验证 claude mcp add/remove、共享配置目录中的写权限和锁，以及 Hook 正常/失败/exit 2 场景；检查组织策略和可观测性，避免输出任何真实 token。

谁可以暂缓

不用 Claude Code/Agent SDK 或没有共享配置和 Hook 的用户可以正常滚动升级，不需要专门迁移。

Pi v1.5.0：工具参数校验切换、MCP OAuth、模型和成本行为

日期：2026-11-02　版本：v1.5.0 · 正式版；历史高价值补看　行动：Test before upgrading

官方原文：https://github.com/earendil-works/pi/releases/tag/v1.5.0

① 官方事实、版本与出处

2026-11-02

② 核心变化与技术机制

工具入参验证换成 @earendil-works/pi-schema；TypeBox 的非标准 JSON Schema 特性如 Type.Refine、Type.BigInt、codec 不再作为工具参数校验能力；MCP OAuth 默认支持 Client ID Metadata；新增扩展更新 changelog、自定义自更新命令和 Usage.cost.totalFromProvider；更新默认 OpenAI 模型为 gpt-6.1-sol，加入 GPT-6.1 Terra。

③ 实际价值

MCP 和扩展的 Schema 一致性、真实账单与估算成本的区分会直接影响第三方中转站和自定义扩展。‘默认模型改变’尤其容易造成意外费用或行为变化，必须在升级前固定模型。

④ 受影响业务与工程场景

Windows PowerShell、自填模型提供商 baseUrl、models.json、全局 pi 安装、自研 Extension/MCP 工具、Tool Calling 参数校验与模型成本仪表盘。

⑤ 风险等级与行动

High · 对自定义扩展可能 Breaking

⑥ Breaking-risk/兼容性

有明确 Breaking Change：超出 JSON Schema 的 TypeBox 参数能力不再应用，旧的自定义扩展可能通过的输入被不同方式处理；错误消息文本也不同。需要对所有自定义工具 schema、数字字符串/数组单值强制转换、MCP/OAuth 回调做回归。

⑦ 回归步骤与谁可忽略

pi --version；备份 ~/.pi/agent/settings.json 与 models.json；固定 defaultProvider/defaultModel；准备 5 组合法、5 组非法输入跑工具参数校验；确认中转站实际 Model ID、Token 计算、MCP OAuth 回调与升级后模型列表。

谁可以暂缓

只用默认 Pi 聊天、没有自定义工具、未启用中转模型的人可以择时升级。

OpenCode：PTY 进程守护进程 0.5.0，主程序仍以 2.2.5 为基线

日期：2026-11-05（PTY）；主程序 2026-10-30　版本：@opencode/pty 0.5.0（protocol 8）；OpenCode 2.2.5（主程序）　行动：Test integrations; no blanket upgrade

官方原文：https://github.com/anomalyco/opencode/releases/tag/process-daemon-v0.5.0 · 关联官方更新

① 官方事实、版本与出处

2026-11-05（PTY）；主程序 2026-10-30

② 核心变化与技术机制

官方发布 process-daemon-v0.5.0，对应 npm @opencode/pty@0.5.0，协议升至 8。OpenCode 用户端最近一次官方主程序 2.2.5 包含百分比 compaction buffer、工作树选择快捷键和 shell mode 切换。两者是不同版本序列，不能把 PTY 组件的发布冒充主程序的发布。

③ 实际价值

嵌入式 Terminal、插件或自建 TUI 会使用进程守护/PTY 协议；协议变更值得校验。对常规 CLI 用户，主程序没有据此变为 0.5.0，也不能据此断定必须升级。

④ 受影响业务与工程场景

使用 OpenCode 桌面会话持久化终端、会话 Shell、PTY 包二次开发、CI Agent、Windows worktree 的团队。

⑤ 风险等级与行动

Medium · 子组件协议兼容

⑥ Breaking-risk/兼容性

PTY 协议号发生变化，但官方简要 Release Notes 未细列 wire-level 破坏点，不推断兼容性保证；消费该组件的项目必须锁定版本并在测试环境验证进程启动/重连/退出和取消。

⑦ 回归步骤与谁可忽略

确认项目实际是否依赖 @opencode/pty；锁定依赖后测试 PTY protocol 8 的握手、stdout/stderr、terminal resize、Ctrl+C 与退出状态；主程序用户核对 opencode --version，并关注 2.2.5 的 compaction.buffer=20% 行为。

谁可以暂缓

不直接使用 PTY/process-daemon 包、不维护终端插件的常规 OpenCode 用户暂时无需动作。
