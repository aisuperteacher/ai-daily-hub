2.1 Code Mode 与 Agent Teams 组合，以及 Skills/Mods 兼容

版本 2.1.326 · 北京时间 2026-11-17 06:11 · 官方来源

变化内容：Claude Code 2.1.326 允许已开启 Code Mode 的 Agent Teams Session 使用 Code Mode；同时修复 Code Mode + Auto Mode 下含内联 ! 命令的 Skills 加载与审批、后台 Subagent 预加载此类 Skill、以及 Mod 经 $.tool.call / $.tool.check 调用 Bash、Read 等工具失败。

技术意义：Code Mode 用 JavaScript 编排多次 Tool Call，Agent Teams 并行分工，两者叠加影响权限、并发、工具结果和失败传播。Code Mode 仍是默认关闭的实验性功能；官方文档指出 Auto Mode 审查代码而非逐一审查内部每个 Tool Call，Resume、Remote Control、后台执行及运行时长均有约束。

不同场景影响

受影响场景严重度方向行动Breaking-risk
自研 Harness、多 Agent、MCP、复杂 Tool CallingHigh利好+权限与并发风险Test before enablingMedium–High
含内联 ! 的 Skills、Mods、插件开发Medium–High兼容利好Test before upgradingMedium

自研 Harness、多 Agent、MCP、复杂 Tool Calling — 检查建议：使用测试 Team 验证工具并行、拒绝、Tool Result ID、超时和失败传播；代码编排不取代权限控制。

含内联 ! 的 Skills、Mods、插件开发 — 检查建议：测试 Auto Mode 审批、后台 Skill 预加载、Mod Tool Call 权限。

谁可以忽略：没有开启 Code Mode/Agent Teams/Mods 的普通 CLI 用户。

2.2 后台 Agent Gateway 丢失时停止请求与 PID 复用安全

版本 2.1.326 · 北京时间 2026-11-17 06:11 · 官方来源

变化内容：修复后台 Session 崩溃、从另一目录重新打开或后台服务缺少 Shell 导出的 LLM Gateway 环境变量时，可能丢失原 Gateway 的问题：现在在不能保留 Gateway 时于新模型请求前停止。另修复 PID 被复用时，后台服务可能错误终止无关 SSH 等进程的问题。

技术意义：Gateway 决定模型请求出口、认证、费用和企业信任边界。静默改走其它 Provider 比直接失败更危险；PID 复用则可能伤及未关联进程。

不同场景影响

受影响场景严重度方向行动Breaking-risk
Windows PowerShell、v2rayN、第三方中转、ANTHROPIC_BASE_URLHigh安全利好+Fail-closed 行为变化Test before upgradingHigh（依赖隐式环境继承时）
SSH、远程 Agent、Self-hosted Runner、长驻服务High进程安全与可靠性利好Upgrade now after canaryMedium

Windows PowerShell、v2rayN、第三方中转、ANTHROPIC_BASE_URL — 检查建议：在测试任务中切后台、退出终端、重开会话及重启后台服务；确认保留预期网关，丢失则明确失败。

SSH、远程 Agent、Self-hosted Runner、长驻服务 — 检查建议：通过无副作用进程检查 Stop、重启、清理不误终止其它进程。

谁可以忽略：没有后台 Session、只用本地交互式官方 Provider 者。

2.3 并行 MCP Tool Result 混淆与服务器身份匹配

版本 2.1.326 · 北京时间 2026-11-17 06:11 · 官方来源

变化内容：修复两个长 MCP Tool Result 在同一毫秒返回时读取对方结果、准确 Tool Name 查找却加载另一个 MCP Server 的工具、相似 Server 名称导致 Prompt 消失、SDK Host 移除 Server 后 Tool 仍尝试重连等问题。

技术意义：Tool Name 不是跨 MCP Server 的全局唯一身份；并行返回必须按 Server、Tool、Call ID 正确关联，并在移除或拒绝后失效。

不同场景影响

受影响场景严重度方向行动Breaking-risk
多 MCP Server、并发 Tool Calls、Agent TeamsHigh数据正确性和权限安全利好Test before upgradingMedium–High

多 MCP Server、并发 Tool Calls、Agent Teams — 检查建议：并行执行两个带不同标识的长 Tool Result，验证无串包；测试相同/相似 Tool Name，不以返回首段当任务完成。

SDK Host 动态增删 MCP Servers — 检查建议：移除 Server 后核验不能凭旧引用重新执行，并验证实际授权与 Tool Discovery。

谁可以忽略：单个 MCP Server、无并发与动态移除的用户。

2.4 MCP Tool Schema 根级 anyOf / oneOf

版本 2.1.326 · 北京时间 2026-11-17 06:11 · 官方来源

变化内容：修复 MCP Input Schema 根节点使用 anyOf 或 oneOf 时只给模型展示第一个分支的问题；升级后数字 42 与字符串 "42" 的生成选择可能不同。mcp add-json 的配置错误提示更明确；本地 Stdio MCP 启动失败在 /mcp 显示具体原因。

技术意义：联合 Schema 应保留所有合法类型，服务端的验证器、类型转换和业务处理必须遵循真实 Schema，不能依赖旧的错误类型选择。

不同场景影响

受影响场景严重度方向行动Breaking-risk
自建 MCP Server、Tool Schema、Java/TypeScript 后端Medium–High协议正确性利好+参数风险Test before upgradingMedium–High
只用普通内置 ToolsLow中性No actionLow

自建 MCP Server、Tool Schema、Java/TypeScript 后端 — 检查建议：测试 string、number、null、对象多分支，确认 Server 校验与处理结果。

只用普通内置 Tools — 检查建议：无需变更。

谁可以忽略：不使用根级联合 Schema 或自建 MCP Tool 者。

2.5 Managed Settings、CLI 权限规则、MCP 托管策略

版本 2.1.326 · 北京时间 2026-11-17 06:11 · 官方来源

变化内容：增加 --allowedTools / --disallowedTools / --tools 不完整规则的启动警告；管理员在运行时新增 managed-mcp.json 导致原 MCP 停止加载时会解释原因。修复 /permissions、工具审批及 /add-dir 在磁盘保存失败后仍假称已保存、部分 Managed Settings Key 干扰其它文件、深嵌套配置崩溃等问题；超过 64 层的设置值被丢弃并发出警告，保存异常也明确指出文件。

技术意义：管理策略和权限是强制控制面。可见的已保存状态必须与真正落盘一致；解析错误不能造成静默权限漂移。

不同场景影响

受影响场景严重度方向行动Breaking-risk
企业 Managed Settings、MCP Deny/Ask、CI/HeadlessHigh安全+配置完整性利好Test before upgradingMedium–High

企业 Managed Settings、MCP Deny/Ask、CI/Headless — 检查建议：检查不完整规则告警、运行时托管 MCP 切换、Deny 生效，区分认证故障、管理员拒绝和解析失败。

Windows 本地配置、共享 Home、多终端保存 — 检查建议：在可销毁环境模拟只读/保存错误，确认不虚报永久保存，不破坏生产托管配置。

谁可以忽略：无托管策略、不用 CLI 权限覆写或动态 /add-dir 的用户。

2.6 PreToolUse Hooks 拒绝审计与错误诊断

版本 2.1.326 · 北京时间 2026-11-17 06:11 · 官方来源

变化内容：Managed PreToolUse 拒绝直接 Tool Call 时，以前可能没有 OTel tool_decision 或 permission_denials；新版修复审计记录。Node/Python Hook 崩溃不再只显示首行堆栈，展开可查看更多输出。新增 OTEL_RESOURCE_INCLUDE_HOST，显式启用才附加 host.name、host.id，默认关闭。

技术意义：安全执行拒绝与 Telemetry 审计要一致；Host 标识可帮助排障但增加主机元数据暴露。

不同场景影响

企业 PreToolUse Hooks、权限审计、OpenTelemetry — 检查建议：以无副作用工具调用验证 Hook 拒绝、真实 Tool 未执行、Telemetry 与 permission_denials 均存在。

Windows PowerShell、Node/Python Hooks — 检查建议：覆盖非零退出、异常与超时；本版不代表 PowerShell Exit Code 2 整体审批语义改变。

2.7 长上下文 Compaction、Vertex 30 MB 与 max_tokens 重试

版本 2.1.326 · 北京时间 2026-11-17 06:11 · 官方来源

变化内容：修复 Bedrock、Vertex、Foundry、关闭 Telemetry 时 Compaction 偶尔回复了用户而没有摘要、遗漏最后 Assistant Reply；Vertex 图片很多时超过约 30MB 请求限制会正确压缩与重试；当 max_tokens 超过 Anthropic API 报告上限时按返回的最大值重试。

技术意义：压缩不仅控制 Token 量，还必须保存正确历史状态；输出 Token 限制不等于 Context Window，非原生网关也未必提供同样错误结构。

不同场景影响

长上下文、Bedrock/Vertex/Foundry、多模型 Subagents — 检查建议：使用可重现长 Session 比较压缩前后指令、最后回复、任务与 Tool Result，检查真实模型限制。

Vertex 多图、第三方 Gateway、输出 Token 预算 — 检查建议：验证 30MB 限制下正常 Compaction/Retry、真实 max_tokens、网关错误返回与费用。

谁可以忽略：短会话、无上述 Provider 与大 Tool Result/图片者。

2.8 Crash/Resume、/rewind 与 claude purge 数据安全

版本 2.1.326 · 北京时间 2026-11-17 06:11 · 官方来源

变化内容：修复 Crash Resume 丢最近 Turn、低内存丢较早历史、操作旧 Session 终止新后台 Session；修复 /branch 两次且备份慢时 /rewind 不完整；当 Shell 修改无法追踪时显示 Code changes unknown 而非 No code changes。claude purge 在 stdout 重定向时确保删除确认仍显示在终端。

技术意义：Session 恢复、文件回滚、破坏性删除都应核实实际数据，不能把 UI 的成功或无变化提示当作事实。

PowerShell 管道、Headless 清理脚本 — 检查建议：确认破坏性提示可见，不依赖不可见确认自动清除项目；非交互清理要单独授权。
