Claude Code 2.1.319

发行日期：2026-11-06 17:04 UTC / 北京时间 11-07 01:04 · 官方来源

2.1 Auto Mode 安全审查策略

变化内容：关闭 Telemetry/Feature Flags、使用第三方 Gateway 且服务端审查不可用时，不再自动回退本地分类器，而是要求人工审批或拒绝。CLAUDE_CODE_AUTO_MODE_SERVER=0 可保留本地分类器旧行为；=1 可在禁用 Experimental Betas 的第三方网关场景显式启用服务端检查；组织托管设置须由管理员协调。Bedrock、Vertex、Foundry 行为保持不变。

技术意义：安全审查与模型推理 API 是不同控制面；模型回答成功不代表操作可以安全执行。

受影响场景：Cloudflare/Nginx/第三方 API Gateway、自定义 BaseURL、Auto Mode

严重度/方向：High／安全利好+兼容风险

行动：Test before upgrading · Breaking-risk：High

检查/迁移建议：在可销毁项目模拟审查成功、403、422、超时、网关未透传，确认 Ask/Deny 行为；未经安全审批不要为了无人值守而关闭检查。

谁可忽略：不使用 Auto Mode/第三方 Gateway 的交互用户

2.2 permissions.denyInsteadOfPrompting

变化内容：新增权限选项，将原本等待人工授权的 Tool Call 直接拒绝，Agent Turn 可继续；适用于终端 Session、Subagents、Teammates。

技术意义：Fail-closed 有利于无人值守，但工具被拒不代表整个任务必然失败，Agent 可能尝试其它工具。

受影响场景：CI/Headless、远程 Agent、定时任务

严重度/方向：High／安全利好+流程变化

行动：Test before adopting / Change config · Breaking-risk：Medium–High

检查/迁移建议：测试 Shell、文件写入、网络和 MCP Tool 被拒后的最终任务状态；不要只依赖模型自然语言的成功声明。

谁可忽略：未启用该权限模式的交互用户

2.3 Subagent/Teammate 权限继承

变化内容：denyInsteadOfPrompting 同样适用于 Subagent 与 Teammate。

技术意义：父 Agent 的提示词并非强制权限边界，必须检查真实策略传播。

受影响场景：多 Agent、团队协作、子代理执行

严重度/方向：High／权限一致性利好

行动：Test before upgrading · Breaking-risk：Medium

检查/迁移建议：分别测试父子 Agent 的 Ask、Deny、工具日志和执行结果。

谁可忽略：不使用多 Agent 的用户

2.4 MCP Tool Task 后台执行

变化内容：MCP Server 将 Tool Call 作为 Task 运行时，Claude Code 可立即转后台并在完成后通知；CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND=1 可测试旧式同步等待。

技术意义：Task 已启动和 Task 已完成不是同一状态；不代表普通 MCP tools/call 全部异步。

受影响场景：MCP、长时数据库任务、远程服务

严重度/方向：High／并发利好+时序风险

行动：Test before upgrading · Breaking-risk：Medium–High

检查/迁移建议：验证完成通知、Resume、取消、网络中断、重复提交、幂等，避免数据库任务尚未完成就重复写入。

谁可忽略：没有 MCP Task 的同步 Stdio 用户

2.5 MCP Task 与 SDK 同步假设

变化内容：后台 Task 改变了部分客户端期望 Tool Result 立即完成的时序。

技术意义：SDK 和测试框架需要显式处理 Task 生命周期。

受影响场景：SDK、CI、Tool Result 解析器

严重度/方向：Medium–High／兼容风险

行动：Test before upgrading / Change config · Breaking-risk：Medium

检查/迁移建议：用 PowerShell 设置 $env:CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND='1' 测试兼容路径；核对 Server Task 支持。

谁可忽略：不解析 Task 状态的用户

2.6 Bash Deny/Ask 权限修复

变化内容：修复带引号单词的 Bash 命令未命中部分 Deny/Ask 规则。

技术意义：降低因 Shell 表达方式不同造成的权限绕过。

受影响场景：Windows Git Bash、Shell 权限规则、PowerShell 互操作

严重度/方向：High／安全利好

行动：Upgrade now after canary · Breaking-risk：Medium–High

检查/迁移建议：可销毁仓库测试引号、空格路径和 Allow/Ask/Deny；不能把 Bash 修复推断为所有 PowerShell 路径已修复。

谁可忽略：无定制权限规则的用户

2.7 claude -p Headless 退出码

变化内容：Auto Mode 安全审查不可用而拒绝操作时，Text/JSON Headless 输出不再错误返回 Exit 0，而返回 Exit 1。

技术意义：CI 将从假成功变成真实失败，原脚本可能暴露问题。

受影响场景：CI/headless、PowerShell 5.1/7、自动化

严重度/方向：High／正确性利好

行动：Test before upgrading · Breaking-risk：High

检查/迁移建议：检查 $LASTEXITCODE、JSON 状态和实际产物，不能仅看 stdout。

谁可忽略：不使用 claude -p 的用户

2.8 claude -p --resume MCP 恢复

变化内容：恢复 Session 时如果缺少未完成 Tool Call 对应的 MCP Server，新版保留调用记录、拒绝后续输入并返回失败。

技术意义：避免静默丢失未完成调用。

受影响场景：Session Resume、MCP、远程 Agent

严重度/方向：High／可靠性利好

行动：Test before upgrading · Breaking-risk：Medium–High

检查/迁移建议：在测试会话断开 MCP Server 后 Resume，核对错误码、调用记录和业务状态。

谁可忽略：不使用 Resume 的用户

2.9 MCP Handshake/Connector 修复

变化内容：修复旧 MCP Handshake Server 扩展能力声明导致连接失败/空结果；claude.ai Connector 长 MCP 调用在 Resume 后不报告结果的问题。

技术意义：改善协议协商和异步结果完整性。

受影响场景：旧 MCP Server、Connector、Session Resume

严重度/方向：Medium–High／可靠性利好

行动：Test before upgrading · Breaking-risk：Medium

检查/迁移建议：验证 Tool List 非空、长任务结果和恢复后调用日志。

谁可忽略：不用旧 MCP 或 Connector 的用户

2.10 Plugins/Skills 更新

变化内容：修复 Plugin 自动更新漏装新依赖，以及 .claude/skills 热重载遗漏文件删除。

技术意义：插件依赖完整性和 Skills Discovery 更可靠。

受影响场景：Windows npm Global、Plugins、Skills

严重度/方向：Medium／可靠性利好

谁可忽略：无插件或动态 Skills 的用户

2.11 配置文件完整性

变化内容：改善 ~/.claude.json、Settings、编辑文件在磁盘满、只读目录、Bind Mount 下可能空文件/截断；多配置文件并存发出警告。

技术意义：降低安全配置和会话文件损坏风险。

受影响场景：共享 Home、容器 Bind Mount、远程 Runner

严重度/方向：High（命中场景）／数据保护利好

行动：Upgrade after canary · Breaking-risk：Medium

检查/迁移建议：模拟磁盘满、只读权限，确认旧文件保留及失败退出。

谁可忽略：无特殊文件系统的用户

2.12 Gateway 预算、日志与费用

变化内容：新增 admin.pooled_conflict_rule、admin.pooled_priority_order；CLAUDE_GATEWAY_LOG_FORMAT=json 提供 severity/time/message；部分 Gateway /usage 展示今日/本周/本月费用。

技术意义：支持团队预算优先级、结构化日志和 FinOps，但 usage 不是最终账单。

受影响场景：企业 Gateway、预算组、日志平台

严重度/方向：Medium–High／治理利好+配置风险

行动：Test before adopting / Change config · Breaking-risk：Medium

谁可忽略：无 Gateway 的个人用户

Codex CLI 0.167.0 Stable

发行日期：2026-11-06 01:40 UTC / 北京时间 09:40 · 官方来源

3.1 系统代理实验接入

变化内容：Windows/macOS 系统代理可通过 TUI /experimental 主动启用；不是默认强制所有请求走系统代理。

技术意义：Windows 系统代理、HTTP_PROXY/HTTPS_PROXY、Provider BaseURL、MCP 出站是不同层。

受影响场景：Windows 11、v2rayN、企业代理、自定义 Gateway

严重度/方向：High／网络兼容利好+路由风险

行动：Test before enabling · Breaking-risk：Medium

检查/迁移建议：比较 DNS、TLS、WebSocket、真实 Provider Host 和 MCP 出站；不能只根据模型正常回复判定代理路径。

谁可忽略：WSL/Linux 或直连用户

3.2 Vertex AI 登录向导

变化内容：Sign in another way 增加 API Key/Cloud Provider 入口；gcp_setup_wizard 支持 Google ADC 或凭据文件配置 Vertex AI。

技术意义：便捷入口不等于获得 IAM、Model、Region、Quota 授权。

受影响场景：Google Cloud、企业多云 Agent

严重度/方向：Medium–High／利好+IAM 风险

行动：Test before adopting · Breaking-risk：Medium

检查/迁移建议：最小权限账号测试 ADC、Project、Region、模型和计费；勿提交服务账户 JSON。

谁可忽略：非 GCP、自定义 OpenAI-compatible 用户

3.3 Agent Command Center

变化内容：新增 codex agents --no-daemon；Command Center/Session Picker 显示未读结果。

技术意义：多 Agent 状态更易观察。

受影响场景：本地/远程 Agent、多 Agent

严重度/方向：Medium／工作流利好

行动：Test before upgrading · Breaking-risk：Medium

检查/迁移建议：核对任务状态、未读结果、实际工作目录。

谁可忽略：个人单会话用户

3.4 跨 Backend 会话与 Transcript

变化内容：Session Picker 切换已连接 Backend 保留草稿；Provider 切换后历史会话不再消失；不可 Resume 的会话仍可查看 Transcript、编辑 Prompt 后继续。

技术意义：历史可见不代表执行上下文、身份、模型、Sandbox 或 MCP 自动迁移。

受影响场景：跨 Provider、远程 Agent、Session Resume

严重度/方向：Medium／恢复利好+兼容风险

行动：Test before upgrading · Breaking-risk：Medium

检查/迁移建议：检查草稿、Transcript、Provider、模型、审批与计费身份。

谁可忽略：单 Backend 用户

3.5 网络审批与并发

变化内容：网络请求结束后审批弹窗及时关闭；同 Endpoint 并发请求依次审批。

技术意义：减少悬挂和重复审批，但不能合并独立授权。

受影响场景：MCP、网络沙箱、CI

严重度/方向：Medium–High／权限体验利好

行动：Test before upgrading · Breaking-risk：Medium

检查/迁移建议：验证每个网络请求的审批边界和结束状态。

谁可忽略：无网络审批用户

3.6 Compaction 与失败响应

变化内容：自动 Compaction 计入失败响应保留输出及缺少 Token Usage 的响应。

技术意义：改善长上下文预算估计和触发时点。

受影响场景：长 Context、第三方 Responses API Gateway

严重度/方向：Medium／压缩正确性利好

行动：Test before upgrading · Breaking-risk：Low–Medium

检查/迁移建议：比较失败响应、缺 Usage、Compaction 触发与成本。

谁可忽略：短上下文用户

3.7 Skills/Plugins/网络规则

变化内容：文档补充 [permissions.network] 托管约束和 prompt-user 命令规则；openai-docs Skill 推荐已废弃模型替代；TUI 加载已安装 Plugin Mentions、Session Plugin 覆盖应用于 MCP 配置刷新。

技术意义：文档补充不是自动扩大权限；插件刷新与 MCP 配置可能影响实际工具可见性。

Cursor Voice Chat with Agents

发行日期：2026-11-06 官方产品更新（无独立 CLI 版本号） · 官方来源

4.1 双向语音 Agent

变化内容：Agents Window、IDE、Web、iOS 可语音讨论修改、查看进度和 Diff、搜索历史、切换 Project Worker；Grok Voice 负责听说，编码仍由当前选定的 Coding Agent 模型完成。

技术意义：语音模型不等于编码模型；远程语音可加速纠偏但不代替代码审查。

受影响场景：移动端、Windows IDE、远程开发、多 Agent

严重度/方向：Medium／生产力利好

行动：Test before adopting · Breaking-risk：Low

检查/迁移建议：用非敏感项目测试；生产部署、合并和删除需完整复核。

谁可忽略：不使用语音者

4.2 隐私、认证、配额及支持范围

变化内容：官方说明 Privacy Mode 下语音零数据保留；Voice Chat 不同于 Dictation。需登录 Cursor 账户，API Key 认证 Session 不支持；有每日额度；Agent 无工作且约十分钟无语音时可挂断。Subagent、Project Worker、归档聊天、Claude Code 聊天和其他成员持有的聊天不显示入口。

技术意义：语音音频处理和跨服务传输仍需遵守组织政策。

受影响场景：企业代码、客户资料、麦克风权限、iOS

严重度/方向：Medium–High／隐私边界风险

行动：Review privacy settings / Test before enabling · Breaking-risk：Low

检查/迁移建议：确认音频数据政策、授权与敏感信息范围；不要朗读 Key、Token、客户资料。

谁可忽略：无麦克风、API Key/CI 或不使用语音者

其它工具：无新正式重大变化
