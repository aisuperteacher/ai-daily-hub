二、Gemini CLI 0.71.1：A2A 安全升级具有明确兼容影响

2.1 A2A Server 强制 Bearer Token、Host/Origin 校验

0.71.1，2026-11-24 11:50（北京），将 PR #30420 回补至 0.71.0。服务器启动时读取 GEMINI_IPC_SECRET，未设置时读取 CODER_AGENT_AUTH_TOKEN；每个 HTTP 请求（包括 Agent Card）都必须带 Authorization: Bearer。缺失/错误令牌为 401；没有配置服务端令牌则返回 500。Host 及存在时的 Origin 必须属于 loopback，否则返回 403。任务创建忽略客户端传入的 isTrusted，按服务端配置判断工作区信任，并校验 workspacePath；restore 限制检查点文件位于检查点目录内。

技术意义：从占位式检查转为服务端真实身份验证和路径边界控制；A2A 与 MCP 是不同协议，不能把该修复解释为所有 MCP 传输都新增认证。

场景 A：远程 Agent、ACP/A2A 集成、代理、CI/headless —— High／安全利好及 Breaking 风险；Upgrade now after canary + Change config；breaking-risk High。同步升级服务端与客户端，验证有效令牌、401、错误 Host/Origin 403、无配置 500；现有反向代理或浏览器跨域调用可能因 loopback 约束失败，不应为了连通而移除校验。

场景 B：普通 Gemini 终端、不运行 A2A Server —— Low／中性；No action（专项配置）；breaking-risk Low；可忽略认证迁移。

PowerShell 测试（已启动本地 A2A 测试服务，令牌来自安全注入的环境变量；不要打印真实令牌）：


$token = $env:GEMINI_IPC_SECRET

if (-not $token) { $token = $env:CODER_AGENT_AUTH_TOKEN }

if (-not $token) { throw 'Missing test token' }

Invoke-WebRequest -Uri 'http://localhost:41242/listCommands' -Headers @{Authorization="Bearer $token"} -UseBasicParsing

# 缺令牌的请求预期返回 401（PowerShell 可能抛出异常）

Invoke-WebRequest -Uri 'http://localhost:41242/listCommands' -UseBasicParsing

来源：0.71.1 Release · PR #30420

3.1 Windows 注册表托管策略启动优先级

启动时 HKLM 托管策略优先于 managed-settings.json，损坏策略值可能阻止启动；修复注册表含非 ASCII 字符导致无法启动的问题。技术意义：企业策略源优先级影响真实权限和启动可用性，不能仅备份 JSON 文件。

Windows 企业受管设备：High／安全治理利好及启动风险；Test before upgrading；breaking-risk High。升级前由管理员核对 HKLM 策略有效性、JSON 配置、实际生效规则及 Unicode，不能擅自删除策略绕过限制。无受管策略的个人 Windows 用户：Low／中性；No action（专项）；可忽略企业策略迁移。

3.2 Hooks、Skills 权限与多 Agent 审批

Stop/SubagentStop 在 Desktop 读取 Transcript 时等待最后回复；PermissionRequest Hook 保存 Skill(name:*) 的允许规则修复；PermissionDenied 的 retry:true 语义调整为只有用户要求该调用时才重试；修复子 Agent 未指定模型时 Agent(model:*) 规则错误阻挡后续消息。

技术意义：Hook 触发时点、Transcript 完整性与权限策略作用域决定自动化审计是否可靠，拒绝后的重试不应被视为无条件授权。

场景 A：PowerShell/自定义 Hooks、Skills 审批、CI —— High／安全及可靠性利好；Test before upgrading；breaking-risk Medium–High。测试最后回复是否可读、Allow 规则存储位置、拒绝后是否真正停止未授权请求。

场景 B：多 Agent/模型权限规则 —— Medium–High／利好；Test before upgrading；breaking-risk Medium。分别测试命名模型与默认模型的子 Agent 创建、后续消息和拒绝路径。无 Hooks、Skills 权限和多 Agent 的用户可忽略专项。

3.3 Plugin 安装、依赖与 11 月 30 日策略预警

技术意义：插件安装图与自动升级属于供应链执行边界；版本、插件代码与生效权限必须分别验证。

企业 Marketplace、定制 Skills/Plugins、npm/global、无人值守安装：High／供应链治理风险与可靠性利好；Change config（审查后）+ Test before upgrading；breaking-risk Medium–High。固定经审核的版本，模拟断网中断安装，检查依赖、组件完整性及审批失败退出；在 11 月 30 日前审查托管 Marketplace。无插件或未使用托管 Marketplace 者可忽略对应专项。

3.4 Code Mode 云 Provider、权限恢复与内存

4.1 Optional Stdio MCP 默认延迟启动

已缓存 Tool Catalog 的 optional Stdio MCP Server 可以在首次调用时才启动，required Server 仍在启动阶段建立连接（#62366）。技术意义：启动更快，但“Tool 可见”不代表 MCP 进程已运行，连接故障可能延后到首次调用。

Windows/npm Global、MCP、本地/远程 Agent：High／性能利好及生命周期变化；Test before upgrading；breaking-risk Medium–High。测试首次调用的启动时延、凭据、进程退出和缓存过期；不要把启动日志当成 Tool Ready。无 Stdio MCP 或无依赖启动副作用者可忽略专项。

4.2 单工具审批 Reviewer

连接应用可以按单个工具配置 approvals_reviewer；优先于连接账户、应用、应用默认值及 Session 设置，但仍受 Managed Requirements 限制（#62360）。先匹配 Tool 原始名，再匹配标题。示例：


[apps.calendar.tools.calendar_create_event]

approvals_reviewer = "user"

技术意义：同一连接中的只读与写入工具可采用不同审批策略；这不是给工具新增执行权限。

企业 Connectors、MCP、Agent 审批：High／细粒度权限利好；Test before adopting / Change config；breaking-risk Medium。测试写入需要人工批准、只读工具按预期执行、Managed Policy 不被覆盖；无连接应用者可忽略。

来源：PR #62360

4.3 Resume 沙箱权限和跨 OS 工作区恢复

codex exec resume 恢复保存的 Sandbox 权限、工作目录及 Workspace Roots（显式覆盖除外）；远程客户端和服务端跨 OS 时保持工作目录、Workspace Roots、Writable Paths；Windows MXC 沙箱迁移到公开 V1 SDK，并补充启动诊断。另暂停了重复的仅遥测 Runtime Integrity Checks（#62389），不等于关闭 Sandbox Enforcement。

Windows PowerShell、远程 Linux/WSL、CI、Headless：High／安全正确性利好及兼容风险；Test before upgrading；breaking-risk Medium–High。测试新会话与 Resume 的实际可写路径、拒绝边界、客户端/服务端路径映射、显式覆盖及启动错误。不要为了恢复任务放宽 Sandbox。仅本地新建短会话且无自定义权限者可忽略专项。

来源：Resume PR #62194 · Integrity Checks PR #62389

5.1 Automation 与 MCP Events

2.4.0 支持定时、间隔、Cron、MCP Event 触发 Prompt、Code Mode 或固定 Shell；Shell 在创建时审批一次并记录每次退出码和输出。/automation 管理任务，设置 "automations": false 禁用。MCP Events 使用 Beta 推送协议，含参数检查、心跳、重连；过大的事件可能跳过。2.4.1 插件新增 ctx.experimental.automation.{create,list,delete}。

定时任务、Windows PowerShell、CI、MCP、多 Agent：High／能力利好及持久权限风险；Test before adopting / Change config；breaking-risk Medium–High。测试任务创建、取消、重启、重复事件与并发、失败重试和审计；Shell 一次批准不意味着所有后续动态行为都已审查，外部写入要做幂等。没有后台自动化需求者可禁用并忽略 API。

企业 IDE、账号会话、Web 自动化：High／能力利好及数据权限风险；Test before adopting；breaking-risk Medium。用隔离测试 Profile，不导入个人或生产登录，核对 Browser Deny、上传、下载、站点权限及取消操作。只用 TUI/CLI 的人可忽略 Desktop 专项。

5.3 Plugins 自动更新、TUI 与 SDK 接口

2.4.0 对 name@latest、版本范围、Git 分支或 semver 范围的插件在启动和每 24 小时自动检查并加载新匹配版本；裸包名、精确版本、非 latest 标签、Git Tag/Commit 不自动更新。新版本加载失败可回退旧插件。Code Mode 路径 tools.opencode.session_rename/session_move 改为 tools.opencode.session.rename/.move，直接 Tool 名与权限操作不变。2.4.0 TUI Plugin Renderer 改接 OpenTUI Block（block.text），删除 codeBlockStyle/escaped；要求 OpenTUI 0.9.4+，2.4.1 又放宽到支持 0.8.0 起的依赖范围。插件恢复后台异步加载，SDK 初始 Model/Provider 等列表可能为空或不完整，不再等待五秒。

场景 A：生产 Plugins、供应链 —— High／自动更新风险；Change config / Test before upgrading；breaking-risk High（依赖动态版本者）。使用已审核的精确版本/Commit，测试热重载、回退、实际权限。

场景 B：自定义 TUI、SDK imports、Code Mode —— High／明确接口迁移；Test before upgrading；breaking-risk High。修改调用路径和 Renderer，监听 model.updated 等事件或等待 plugin.list/目标条目，别把启动初期空列表当永久不可用。

### 2.1 A2A Server 强制 Bearer Token、Host/Origin 校验

0.71.1，2026-11-24 11:50（北京），将 PR #30420 回补至 0.71.0。服务器启动时读取 GEMINI_IPC_SECRET，未设置时读取 CODER_AGENT_AUTH_TOKEN；每个 HTTP 请求（包括 Agent Card）都必须带 Authorization: Bearer。缺失/错误令牌为 401；没有配置服务端令牌则返回 500。Host 及存在时的 Origin 必须属于 loopback，否则返回 403。任务创建忽略客户端传入的 isTrusted，按服务端配置判断工作区信任，并校验 workspacePath；restore 限制检查点文件位于检查点目录内。

来源：[PR #62366](https://github.com/openai/codex/pull/62366)

### 4.2 单工具审批 Reviewer

连接应用可以按单个工具配置 approvals_reviewer；优先于连接账户、应用、应用默认值及 Session 设置，但仍受 Managed Requirements 限制（#62360）。先匹配 Tool 原始名，再匹配标题。示例：
```toml
[apps.calendar.tools.calendar_create_event]
approvals_reviewer = "user"
```
技术意义：同一连接中的只读与写入工具可采用不同审批策略；这不是给工具新增执行权限。

企业 Connectors、MCP、Agent 审批：High／细粒度权限利好；Test before adopting / Change config；breaking-risk Medium。测试写入需要人工批准、只读工具按预期执行、Managed Policy 不被覆盖；无连接应用者可忽略。
来源：[PR #62360](https://github.com/openai/codex/pull/62360)

### 4.3 Resume 沙箱权限和跨 OS 工作区恢复

codex exec resume 恢复保存的 Sandbox 权限、工作目录及 Workspace Roots（显式覆盖除外）；远程客户端和服务端跨 OS 时保持工作目录、Workspace Roots、Writable Paths；Windows MXC 沙箱迁移到公开 V1 SDK，并补充启动诊断。另暂停了重复的仅遥测 Runtime Integrity Checks（#62389），不等于关闭 Sandbox Enforcement。

Windows PowerShell、远程 Linux/WSL、CI、Headless：High／安全正确性利好及兼容风险；Test before upgrading；breaking-risk Medium–High。测试新会话与 Resume 的实际可写路径、拒绝边界、客户端/服务端路径映射、显式覆盖及启动错误。不要为了恢复任务放宽 Sandbox。仅本地新建短会话且无自定义权限者可忽略专项。
来源：[Resume PR #62194](https://github.com/openai/codex/pull/62194) · [Integrity Checks PR #62389](https://github.com/openai/codex/pull/62389)

### 4.4 Code Mode gRPC、模型迁移与 Provider 错误

Code Mode 所有 Host Connections 使用 gRPC，code_mode_host_grpc 弃用；App-server Setup/Sign-in 支持 Amazon Bedrock Runtime；流式 Provider 错误即时报告，并区分 API 消费上限；openai-docs Skill 补充 GPT-6.2 Astra/Sol 端点和 Tool Calling 迁移说明。父 Turn 中断后保留子 Agent 排队回复；TUI 支持 Thread Links、命令补全及任务组导航。

场景 A：自研 Host、SDK imports、Code Mode、第三方 Provider —— Medium–High／迁移风险；Test before upgrading / Change config（审查弃用字段）；breaking-risk Medium–High。测试 gRPC 连接、远程 Host、Stream Error、SDK JSONL、模型 Tool Schema 与真实费用。
场景 B：多 Agent、TUI —— Medium／利好；Test before upgrading；breaking-risk Low–Medium。测试中断后子 Agent 消息不丢失，避免把保留回复当作新执行。未使用 Code Mode/SDK 或多 Agent 的个人用户可忽略专项。

## 五、OpenCode 2.4.0 与 2.4.1：Agent 自动化与插件生态发生实质变化

补报原始发布日期：2.4.0 为 2026-11-23 09:22 UTC（北京 17:22）；2.4.1 为 11-23 15:57 UTC（北京 23:57）。两者为 V2 正式发行；V1 仍为 1.19.6。
来源：[2.4.0 Release](https://github.com/anomalyco/opencode/releases/tag/v2.4.0) · [2.4.1 Release](https://github.com/anomalyco/opencode/releases/tag/v2.4.1) · [npm V2](https://www.npmjs.com/package/@opencode/cli?activeTab=versions)

### 5.1 Automation 与 MCP Events

2.4.0 支持定时、间隔、Cron、MCP Event 触发 Prompt、Code Mode 或固定 Shell；Shell 在创建时审批一次并记录每次退出码和输出。/automation 管理任务，设置 "automations": false 禁用。MCP Events 使用 Beta 推送协议，含参数检查、心跳、重连；过大的事件可能跳过。2.4.1 插件新增 ctx.experimental.automation.{create,list,delete}。

定时任务、Windows PowerShell、CI、MCP、多 Agent：High／能力利好及持久权限风险；Test before adopting / Change config；breaking-risk Medium–High。测试任务创建、取消、重启、重复事件与并发、失败重试和审计；Shell 一次批准不意味着所有后续动态行为都已审查，外部写入要做幂等。没有后台自动化需求者可禁用并忽略 API。

### 5.2 Desktop Browser 与持久化身份

2.4.0 内置浏览器可导入 Chrome/Edge/Firefox/Safari 登录状态和历史，支持扩展、持久 Profile 与 Agent 操作；browser Deny 可以拒绝 Agent 浏览器调用。

企业 IDE、账号会话、Web 自动化：High／能力利好及数据权限风险；Test before adopting；breaking-risk Medium。用隔离测试 Profile，不导入个人或生产登录，核对 Browser Deny、上传、下载、站点权限及取消操作。只用 TUI/CLI 的人可忽略 Desktop 专项。

### 5.3 Plugins 自动更新、TUI 与 SDK 接口

2.4.0 对 name@latest、版本范围、Git 分支或 semver 范围的插件在启动和每 24 小时自动检查并加载新匹配版本；裸包名、精确版本、非 latest 标签、Git Tag/Commit 不自动更新。新版本加载失败可回退旧插件。Code Mode 路径 tools.opencode.session_rename/session_move 改为 tools.opencode.session.rename/.move，直接 Tool 名与权限操作不变。2.4.0 TUI Plugin Renderer 改接 OpenTUI Block（block.text），删除 codeBlockStyle/escaped；要求 OpenTUI 0.9.4+，2.4.1 又放宽到支持 0.8.0 起的依赖范围。插件恢复后台异步加载，SDK 初始 Model/Provider 等列表可能为空或不完整，不再等待五秒。

场景 A：生产 Plugins、供应链 —— High／自动更新风险；Change config / Test before upgrading；breaking-risk High（依赖动态版本者）。使用已审核的精确版本/Commit，测试热重载、回退、实际权限。
场景 B：自定义 TUI、SDK imports、Code Mode —— High／明确接口迁移；Test before upgrading；breaking-risk High。修改调用路径和 Renderer，监听 model.updated 等事件或等待 plugin.list/目标条目，别把启动初期空列表当永久不可用。
谁可忽略：不安装定制 Plugins、不使用 SDK/Code Mode 的普通用户。

### 5.4 MCP 协商与 Provider 认证

2.4.0 未设置 protocol 的 MCP Server 优先尝试新协议，再回退旧握手；有故障的旧 Server 可设 protocol: "legacy"。GitHub Copilot 不再读取 GITHUB_TOKEN，应改 COPILOT_GITHUB_TOKEN 或 OAuth。ChatGPT Plan 模型列表从 models.dev 获取，注销 ChatGPT 登录时也向 OpenAI 撤销；Provider timeout 覆盖更多生成/压缩请求。2.4.1 修复仅有 config、未 /connect 登录的 Ollama 等 Provider 在 /models 不显示。

MCP/自定义 Provider、GitHub Actions、Windows、第三方 Gateway：High／兼容及认证变化；Change config + Test before upgrading；breaking-risk High（依赖旧变量者）。测试 MCP 握手、Token 最小权限、模型发现、真实授权、超时和注销；不要将 GITHUB_TOKEN 当 Copilot 凭据。没有这些集成可忽略专项。

### 5.5 Compaction、模型速度和存储

2.4.0 Assistant Parts 独立行持久化，可用 experimental.part_rows:false 恢复旧写入路径（本发行版）；保存的 Blob 一周后清理，项目中保存的副本不受影响。2.4.1 修复 keep.tokens 保留超量历史和长 Goal Session 额外缓存费用，以及 macOS 12 SQLite 保存故障；experimental.model_speeds 启用后，Service Tier 成为可记忆的速度选项，/speed、/fast 显示相对价格。

长 Context、远程 SDK、存储、成本：Medium–High／可靠性利好及计费/迁移风险；Test before upgrading；breaking-risk Medium。验证数据库备份、历史读取、Compaction Token 上限、缓存命中、Blob 下载生命周期、实际 Service Tier 与费用。短会话且不改速度或存储设置者可忽略专项。

### 5.6 工具改名与视频任务

2.4.0 experimental_image_generate 改名 generate_image，旧 Permission Rules 自动映射但已保存 Always Allow 审批不迁移，需要重新审批；generate_video 在已连接 Provider 支持时运行后台任务，支持重启恢复及工作区保存，默认模型 experimental.video_generate.model。Windows Taskbar 可显示待处理权限和任务状态。

工具权限、AI 视频生产和后台任务：Medium–High／能力利好及兼容风险；Test before upgrading；breaking-risk Medium。更新依赖工具名的脚本，验证重新审批、模型费用、生成失败、恢复及文件落地。未用图像/视频工具者可忽略。V1 1.19.6 升级 V2 需先验证插件兼容，不要把两个 npm 发行线当同一包。
