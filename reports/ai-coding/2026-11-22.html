二、Claude Code 2.1.330：官方重要变化

发布： 2026-11-20 22:32 UTC = 北京时间 2026-11-21 06:32。来源：GitHub Release v2.1.330，npm 最新包元数据。

2.1 Enterprise Admin Console 登录继承组织配置和 Gateway

变化内容： claude auth login 可以登录 Anthropic Enterprise Admin Console 管理的组织，并应用该组织的设置和 Cloud Provider / Gateway；新增 CLAUDE_CODE_FULL_SIGN_IN_LINK=1 以在短登录链接失败时输出完整登录 URL。

技术意义： 身份认证成功与实际执行的模型出口、组织策略、Permission Rules、费用归属不同，企业登录可能使新会话自动应用组织级配置。完整登录链接可能包含敏感或短时授权数据，不能打印到公开日志。

场景 A — 企业 SSO、第三方 API Gateway、Bedrock/Vertex/Foundry： High／治理利好 + 路由风险；Test before upgrading / Verify config；breaking-risk Medium–High。 用测试身份验证组织 ID、请求实际 Provider、Model ID、代理出口、Managed Settings 与身份回退；不可把已登录等同于 Gateway 路由正确。

场景 B — Windows PowerShell、SSH / Headless 认证： Medium／认证便利 + 日志风险；Test before adopting；breaking-risk Low–Medium。 若需要完整登录 URL，只在受控终端使用 CLAUDE_CODE_FULL_SIGN_IN_LINK=1，不要将登录链接复制到 CI 公共日志。

谁可以忽略： 不使用企业托管组织、只使用既有个人认证的用户。

2.2 Self-hosted Runner 工作目录、插件来源和结构化安装结果

变化内容： 新增 --start-dir / SELF_HOSTED_RUNNER_START_DIR，让自托管 Runner 从仓库的某个子目录工作，同时保持原有 Settings / Hooks 加载规则；当 Cloud/Runner 无法取得不属于会话仓库的 Plugin Marketplace 或 Anthropic 托管 Git 阻止插件自有仓库时，会明确提示。claude plugin install --json 新增 commandPrinted 和 commandFailed；Runner 增加「工单→注册」和「工单→首次 Session」时长指标。

技术意义： 启动工作目录、项目指令发现、Hook 加载和插件源码信任是不同控制面。插件安装命令打印了 stderr 不等于执行失败，应分别看 commandPrinted / commandFailed。

场景 A — 远程 Agent、Monorepo、Git Worktree、Self-hosted CI： Medium–High／可控性利好 + 路径兼容风险；Test before adopting；breaking-risk Medium。 在测试仓库核对从子目录启动后的 CWD、相对文件路径、Hooks、CLAUDE.md 加载和仓库边界；不能据此假设权限限定在子目录。

场景 B — Plugin Marketplace、自动安装脚本、监控： Medium／诊断利好 + API 结果变化；Change parsing / Test before upgrading；breaking-risk Low–Medium。 对 --json 返回新增字段使用宽容解析，检查插件真正安装状态；Metrics 统计排队/启动延迟，不代表任务成功完成。

谁可以忽略： 不使用 Self-hosted Runner、远程插件市场或解析插件安装 JSON 的用户。

2.3 并发 Worktree 删除、Rewind 和持久配置竞态修复

变化内容： 修复 ExitWorktree 或退出对话框误删另一个仍在运行的 Claude Session 所用 Worktree；多个 Claude 进程同时保存 User Settings 时更改丢失；多个 Task Update 导致依赖与元数据丢失；磁盘满时不完整的 ~/.claude.json 备份覆盖良好备份；紧邻文件修改的排队 Prompt/嵌套 Skills 使 /rewind 恢复到错误版本。

技术意义： Session 生命周期、文件归属、任务元数据和备份是持久化一致性问题，不能只靠 UI 提示「已退出」「已恢复」判定安全。

场景 A — Git Worktree、多 Agent、并发 Claude CLI： High／数据保护利好；Upgrade after canary；breaking-risk Medium。 在临时仓库中开启两个 Session，检查退出一个后另一个 Worktree 仍存在，并通过 git status/git diff 核对 /rewind 后文件内容。

场景 B — Windows 并行终端、企业多任务、低磁盘空间： High／配置完整性利好；Test before upgrading；breaking-risk Low–Medium。 预备份无密钥测试配置；验证并发配置保存后 Settings、Task Dependencies 和 Backup 都完好，避免在生产主目录测试磁盘耗尽。

谁可以忽略： 只有单 Session 且不使用 Worktree、Rewind 或并发任务的用户可忽略专项测试。

2.4 Windows Git Bash、WSL 休眠重连、长上下文与 WebFetch

变化内容： 修复 Windows 上 Git Bash 启动耗时约 10–60 秒后，后续 Bash 命令持续变慢；Linux/WSL 休眠超过两分钟后第一次 Prompt 等待旧连接约三分钟；超长会话自动 Compaction 后冻结；WebFetch 读取特定网页卡住或返回空结果。

技术意义： Shell 启动成本与后续命令生命周期、失效网络连接重试、Compaction 和 WebFetch 属于独立路径，修复旨在提高稳定性，而不表示所有代理超时或网站访问问题都已解决。

场景 A — Windows 11 + PowerShell 调用 Git Bash： Medium–High／性能利好；Test before upgrading；breaking-risk Low–Medium。 在相同仓库比较首条与后续 Shell 执行耗时、Exit Code、中文路径及代理环境变量，检查 Git Bash 启动脚本影响。

场景 B — WSL、长 Context、代理环境中的 WebFetch： Medium–High／可靠性利好；Test before upgrading；breaking-risk Low–Medium。 休眠再恢复测试、超长对话摘要是否保留关键任务、网页抓取空结果及网络代理行为；不要以「没有卡死」替代最终数据校验。

谁可以忽略： 不使用 Git Bash/WSL、长上下文或 WebFetch 的用户。

2.5 MCP Input Schema、共享 Server 生命周期与 Connector 发现

变化内容： 多个 MCP Tools 使用上游 API 不接受的 Input Schema 时，旧版可能使模型 Turn 报 JSON schema is invalid 且会话文件增长很多 MB；现在修复。Subagent 声明的 MCP Server 不会在其中一个子 Agent 结束时被误关（其它 Agent 仍在使用）；终端 @Mention 的 Connector / Plugin MCP Resources 可以正确附加；不同名称但共享 Server URL 的 claude.ai Connectors 不再被错误去重。

技术意义： Schema Validation、Server Session 引用计数、资源身份及工具可见性是 MCP 的关键边界；单纯按 URL 或 Server 名称去重会丢失逻辑资源。

场景 A — 自建 MCP、Java/TypeScript Tool Schema、第三方 Gateway： High／协议正确性利好；Test before upgrading；breaking-risk Medium。 用测试 oneOf/anyOf、无效属性及多个 Server 对比 Tool Discovery、上游返回错误、会话文件增长和结果类型；无效工具不应使整个 Session 崩溃。

场景 B — 多 Agent、Plugin MCP、同 URL 的不同 Connector： High／工具生命周期利好；Test before upgrading；breaking-risk Medium。 并发启动/结束不同 Subagents，验证仍在使用的 MCP Server 未被过早关闭，@Mention 注入实际资源正确且权限未扩大。

谁可以忽略： 单独使用简单内置 Tools、不使用 MCP/Connector 的用户。

2.6 Code Mode、背景权限状态、Hooks 与 Headless 返回码

变化内容： Code Mode 修复读取数百文件并遇到 Path-scoped Rules / Read Deny 后长时间停顿；修复 MCP Tool 请求结束 Turn 时被忽略、Auto Mode 中 Mod 提示改变 Thinking 与 Prompt Cache、Esc 加 /compact 后文件未正确恢复；背景 Subagent Stop 不生效或继续等待，以及批准 Plan 后沿用旧 Permission Mode。SessionStart Hook 写入的环境变量在 claude -p --continue 中得以保留。重定向输出至已满磁盘时，claude -p 不再无消息返回 Exit 0，而是报错并 Exit 1（部分 NFS 满盘场景仍有限制）。

技术意义： Code Mode 的 JavaScript Tool 编排与 Tool-level Permission、状态恢复、主进程 Exit Code 不能脱钩；Exit 0 应与真正成功写入结果一致。

场景 A — Code Mode、Agent Teams、Skills / Mods、MCP： High／权限与执行正确性利好；Test before upgrading；breaking-risk Medium–High。 测试 Read Deny、停止子 Agent、MCP 结束 Turn、取消+Compaction 的文件状态及真实 Tool Call 副作用。

场景 B — CI/Headless、PowerShell Hooks、远程 Runner： High／可靠性利好 + Exit Code 行为变化；Test before upgrading / Change error handling；breaking-risk Medium。 测试 SessionStart 配置环境变量的保存与 Headless 输出写入错误，确保 CI 把非零退出当失败，不吞掉 stderr。

谁可以忽略： 不启用 Code Mode、后台 Agent、Hooks 或 claude -p 的用户。

2.7 其它修复：模型选择、LSP、CLAUDE.md 与缓存

变化内容： 修复 Bedrock Mantle 未选模型时忽略固定的 Opus Model；Google Agent Platform 在 --settings '{"fastMode":true}' 与 ANTHROPIC_MODEL 组合下未启用 Fast Mode（修复后可能按 Fast Mode 费率计费）；修复 LSP 启动过程的并发诊断失败与 Esc 取消无效、CLAUDE.md 含 HTML 注释时丢失 Markdown 引用链接、同名用户/项目 Agent 由文件搜索顺序随机选中、Plugin 并发安装时列表缺失，以及 /mcp 对 Plugin Server 归类错误。

技术意义： 这是模型路由/成本、IDE Tool Lifecycle、Instructions 文件解析及 Skills/Plugin Discovery 的一致性修复。

场景 A — Bedrock/Vertex/Gateway、模型或 Fast Mode 成本敏感： High（对应 Provider）／准确性利好 + 费用变化风险；Verify config / Test before upgrading；breaking-risk Medium。 核对请求 Model ID、实际 Fast Mode、Token 费用和账户限额，不因 UI 文案默认认为费率没变。

场景 B — IDE LSP、自定义 Agents、CLAUDE.md、Plugins： Medium／兼容利好；Test before upgrading；breaking-risk Low–Medium。 并发运行 LSP、Esc、Markdown 引用、同名 Agent 和 Plugin 安装测试，确认按预期的加载层级和身份执行。

谁可以忽略： 不使用指定模型路径、LSP、自定义 Instructions 或 Plugin 的用户。

三、Gemini CLI 0.69.0 / 0.70.0：补报安全与 Windows 变化

真实发布日期： 0.69.0 为 2026-11-19 01:45 UTC / 北京时间 11 月 19 日 09:45；0.70.0 Stable 为 2026-11-19 21:08 UTC / 北京时间 11 月 20 日 05:08。当前正式 Latest 是 0.70.0，0.71.0-preview.0 与 Nightly 均不是 Stable。来源：0.69.0 Release、0.70.0 Release、官方 Stable Changelog。

3.1 Policy Engine：re2js、Shell Regex 与未知变量必须 Ask

变化内容： 0.70.0 让 Policy argsPattern 使用 re2js 进行线性时间正则匹配，降低恶意或复杂 Regex 的 ReDoS 风险；commandPrefix、commandRegex 改为匹配 Shell Tool 顶层 Command 参数；对无法解析变量展开的 Shell Command 保持 ASK_USER，避免误判已批准。

技术意义： Shell 授权应依据真正的命令参数及未知展开结果，不应仅靠字符串中的一部分匹配放行；Regex 选择也影响规则匹配效率及语义。

场景 A — Windows PowerShell 5.1/7、Shell Allow/Deny、企业 Policy： High／安全利好 + 旧规则兼容风险；Test before upgrading；breaking-risk Medium–High。 在可销毁仓库核验 $env:、变量拼接、嵌套命令、Policy Regex、ASK_USER、大小写及引号；不要通过全局放开 Shell 规避新审批。

场景 B — Headless CI、自动审批的 Agent： High／安全利好 + 无人值守卡住风险；Change config / Test before upgrading；breaking-risk High（依赖旧模糊 Allow 规则者）。 将需要的命令显式限定为可审核参数；无法判定时拒绝或终止自动化，而不是静默允许。

谁可以忽略： 不使用 Shell Tool 或自定义 Policy 的用户。

3.2 系统 MCP Server 权限和 Symbolic Link 目标确认

变化内容： 0.70.0 会跳过 Command Permission 不安全的 System MCP Servers；涉及链接时向用户披露 Canonical Target Path，相关 Consent 默认选 No。

技术意义： 配置列出 MCP Server 并不代表可以可信执行；Symlink/别名路径可能隐藏真实文件目标。升级后原先能启动的 Server 可能因权限检查被拒绝，这是需要处理的安全信号。

场景 A — Windows + MCP、系统级 Server、自定义服务： High／安全利好 + 兼容风险；Test before upgrading；breaking-risk High（Server 权限不规范时）。 检查安装目录和文件访问控制、Server 权限来源、拒绝原因和 Tool Discovery；不要直接禁用检查。

场景 B — 符号链接、WSL、多个工作目录： Medium–High／透明度利好；Test before upgrading；breaking-risk Medium。 对可销毁测试目录检查 Canonical Target 与工作区边界，确认不会因为链接名而误授权写入外部目录。

谁可以忽略： 不使用系统 MCP 或链接目录的用户。

3.3 Windows PowerShell 变量、ACP / Headless 流水线及终止语义（0.69.0）

变化内容： 0.69.0 修复 PowerShell 命令变量替换的误报和 Policy 处理；模板中的字面量 $ 不再被错误替换；管道 stdin 会等待 EOF，不再错误销毁 process.stdin；Headless Abort 会正确结束子进程、记录被取消的工具并保留信号 Exit Code；ACP Tool Call 更新中的 ANSI Output 正确序列化，失败输出也更规范。

技术意义： $ 在 PowerShell 和模板中具有不同含义；错误展开可能导致执行不符合预期的命令。Headless Abort 必须清理子进程并将真实终止状态报告给宿主。

场景 A — Windows 11、PowerShell 5.1/7、含 $ 的 Hooks/Commands： High（此前误解析者）／正确性利好；Test before upgrading；breaking-risk Medium。 用不含密钥的本地脚本检查字面量 $、$env:、管道输入 EOF、命令实际参数和 Exit Code。

场景 B — ACP 客户端、IDE、CI/Headless： Medium–High／协议与取消稳定性利好；Test before upgrading；breaking-risk Medium。 模拟长进程取消，检查子进程退出、ACP Tool Result 是否重复/拼接和最终退出信号。

谁可以忽略： 不使用 PowerShell 特殊变量、ACP 或 Headless 模式的用户。

3.4 Model API Timeout、429 重试、请求体与模型列表

变化内容： 0.69.0 支持跨认证模式调整模型请求 Header Timeout：model.requestTimeoutMs / GEMINI_API_HEADERS_TIMEOUT_MS，并修复静默卡住和多小时的 Quota Retry；0.70.0 在设置超过默认 300 秒的 Request Timeout 时同步扩展 Undici bodyTimeout，改进模型目录显示的 Output Token Limits 和 Auth Capabilities。

技术意义： Header Timeout、Body Timeout、整体业务 Job Timeout 是不同约束；单独提高上限可能拖慢故障发现。模型目录标注修正也不代表 Provider 真正开放了额外 Token 配额。

场景 A — 代理/v2rayN、第三方 Gemini Gateway、长上下文： Medium–High／稳定性利好 + 超时配置风险；Test before upgrading / Change config if needed；breaking-risk Medium。 用本地 Mock Server 做延迟响应头、长响应体和超额 429，验证重试上限、实际请求终止及代理行为。

场景 B — CI/Headless、成本敏感： Medium／诊断利好；Test before upgrading；breaking-risk Low–Medium。 保留独立 CI 外层超时并检查真实退出码，避免内部重试无限占用构建配额。

谁可以忽略： 不用长请求、不碰 Quota Retry、只用默认参数且运行稳定的用户。

3.5 IDE 发现隔离、Worktree/Resume、Skills / Instructions 与多模态

变化内容： 0.70.0 把 IDE Companion Discovery 改为 Per-user 目录并原子写入端口文件；认证重启保留选定 Worktree，只有 Chat Resume 成功才恢复 Workspace Directories；${VAR:-default} 中变量设为空字符串时正确使用默认值，Session Preview 保留 Unicode 并去掉 ANSI 噪声。0.69.0 还修复 @file 引用首尾空白丢失、多模态 Tool Response 缺失和中途流式重试文本拼接，收紧一次性内联的二进制资产边界。

技术意义： IDE 端口文件是本地控制面发现信息，必须避免不同用户互相干扰；Workspace、Worktree 与 Prompt 引用的实际文件范围则关系到 Agent 恢复后的安全与数据完整性。

场景 A — VS Code/IDE、Windows 多用户、本地 Agent： Medium–High／隔离利好；Test before upgrading；breaking-risk Medium。 验证多个 Windows 用户/IDE Window 的 Discovery、端口文件读写、连接退出和重新发现。

场景 B — Worktree、AGENTS.md/GEMINI.md 项目规则、Session Resume： Medium–High／可靠性利好；Test before upgrading；breaking-risk Medium。 检查重连后当前目录、已信任目录、Rule Discovery、@file 实际内容和 Workspace 范围，不应把 GEMINI.md 与别的工具规则当成统一优先级。

场景 C — 多模态、ACP、文件处理： Medium／结果完整性利好；Test before upgrading；breaking-risk Low–Medium。 验证图片、文本混合 Tool Responses 和失败重试后是否丢失/拼接内容。

谁可以忽略： 不使用 IDE 集成、跨目录恢复或多模态工具的用户。
