1. agent-substrate/substrate

官方 GitHub：agent-substrate/substrate

近期热度与活动：Go 榜 8,351 Star，+64；11/20 v1.0.1

技术栈／语言：Go、Kubernetes、gVisor、Cloud Hypervisor、SPIFFE

主要用途：将有状态 Agent 映射到共享 worker，空闲时保存内存和文件系统状态，请求到来时恢复。

核心优点：减少空闲 Agent 占用；身份、出站授权与执行隔离分层。1.0.1 加固出站地址限制，并改善恢复超时后的重试语义。

成熟度与维护活跃度：已达 1.0，11/20 补丁发布；仍是年轻的基础设施项目，支持范围需核对。

适合人群／场景：长任务 Agent、多租户执行平台、Kubernetes 资源治理

是否值得关注：★★★★★｜Top 1

行动建议：60 分钟：在隔离集群让测试 Agent 休眠并恢复，验证状态、网络拒绝、恢复延迟与重复请求。

四、技术趋势与行动建议

运行时与编排分层：Substrate 管执行、隔离与状态，Kestra 管流程，Multica 管团队任务；三者并非已验证的开箱即用集成。

Agent 记忆要有迁移策略：Beads 的单向 schema 迁移说明持久状态必须备份，不能把 Agent 重启当成数据库回滚。

传统基础设施仍不可替代：Spring Boot、SkyWalking、Strimzi、Keycloak 分别解决应用运行、观测、消息部署与身份治理。

高增长工具仍需验收：CLI-Anything、Firecrawl 和下载管理工具应按权限、结果正确性、成本及维护能力评价。

如果只有 90 分钟：先用 45 分钟验证 Kestra 的失败重试与重复写入，再用 45 分钟验证 Multica 的任务依赖。Substrate 需要独立集群，留作专项实验。所有实验仅使用公开、自有或虚构测试数据。未独立运行性能、安全、成本 Benchmark；成熟度、优缺点、关注等级和时间预算为工程判断。
