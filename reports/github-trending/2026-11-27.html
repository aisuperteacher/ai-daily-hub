01｜apache/nifi：数据流调度进入虚拟线程时代

官方地址：apache/nifi

用途与技术栈：可视化构建数据采集、路由、转换与传输流程；Java、FlowFile、Processor、数据流调度和数据溯源。

热度与活动：6,339 Star，Java 榜 +5。11 月 26 日发布 2.13.0，官方记录解决超过 215 个问题，新增 Processor 虚拟线程调度、无状态流程内存内容存储和 Protobuf Record Writer。

优点：数据流、队列与背压具有可观察的工程抽象；虚拟线程为大量阻塞 I/O 的调度提供新选择。

局限：虚拟线程不会加速 CPU 密集计算，也不会自动扩大数据库连接池；内存存储须评估容量和故障语义。

成熟度与维护：高，Apache 长期维护，11 月 26 日正式发布。

适合场景与关注度：企业数据集成、数据管道、Java 并发研究；★★★★★，今日 Top 1。

行动建议：60 分钟，在测试流程比较传统与虚拟线程调度的吞吐、P95、内存与下游连接数，注入慢响应验证背压。

来源：nifi Releases

02｜pingdotgg/t3code：跨仓库 Coding Agent 控制平面

官方地址：pingdotgg/t3code

用途与技术栈：统一管理本地 Codex、Claude Code、Pi 等 Agent 的会话、审批和 Git Worktree；TypeScript、Web/桌面客户端、Agent CLI、ACP。

热度与活动：11 月 26 日七日榜 +14,487 Star，累计 80,670。11 月 25 日稳定渠道 0.1.12 增加多仓库项目、Beta 持久工作流及关联线程；同日 Nightly 进一步加入工作流并发限制。

优点：让多个仓库的任务、代码差异与人工批准集中管理，支持 Windows。

局限：Beta 与 Nightly 功能不能视为成熟生产能力；远程控制扩大文件、命令及凭据的安全边界，Worktree 不等于安全沙箱。

成熟度与维护：成长阶段，0.x 版本，近期稳定版与 Nightly 均有发布。

适合场景与关注度：多模块研发、跨仓库 Agent 任务、远程审批；★★★★★，今日 Top 2。

行动建议：45 分钟，用两个自有测试仓库建立跨仓库任务，验证审批拒绝、任务取消、合并冲突和恢复；不开放公网控制端口。

来源：t3code Releases

成熟度与维护：高，长期维护，近期有明确安全补丁。

适合场景与关注度：Java 开发、SQL 调试、数据库运维；★★★★★，今日 Top 3。

行动建议：20 分钟，核对当前版本及实际运行 JRE，备份配置后通过官方渠道更新，并验证测试库连接与导出功能。
