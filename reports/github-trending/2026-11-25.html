1｜datazip-inc/olake-go：数据库 CDC 与湖仓同步

官方 GitHub：datazip-inc/olake-go

主要用途：将数据库、Kafka、S3 数据复制到 Iceberg 或 Parquet，支持多种数据库源。

技术栈／语言：Go、CDC、Apache Iceberg、Parquet、Kafka、Docker

近期热度／活动：2,316 Star；11/24 Go 日榜第 1，+51；11/20 v1.2.2

核心优点：把事务库与分析存储解耦；可连接 Polaris 等 REST Catalog，便于多引擎共享数据。

主要缺点／局限：v1.2.2 引入 MongoDB resume token 支持，但运行 MongoDB CDC 后状态和目标元数据格式改变，官方明确不能降级至 v1.2.1 或更早版本；各连接器的增量、删除及 Schema 演进能力不能一概而论。

成熟度与维护活跃度：中等偏高；11/19、11/20 连续发布，工程维护积极。

适合人群／场景：企业数据同步、CDC、实时湖仓、Java 微服务数据架构。

是否值得关注：★★★★★ · Top 1

行动建议：60 分钟：在隔离 MongoDB 测试库演练升级、断点恢复、重复事件和备份恢复；不要尝试不受支持的原地降级。

依据：官方仓库或发布说明

三、今日 Top 3

四、技术趋势与行动计划

趋势 1：数据基础设施的关键不只是吞吐，而是状态兼容：OLake 与 Polaris 分别解决数据复制和元数据目录问题，升级与恢复需独立设计。

趋势 2：Agent 工程要把测试与隔离分开：LangChain4j 验证调用行为，OpenSandbox 管执行环境，Dependency-Track 监控依赖风险。

趋势 3：消息语义仍是架构基本功：NATS 的 Core 与 JetStream 可用于对照消息持久化、重试和业务幂等。

趋势 4：从原理到产品可以形成小闭环：MiniMind 学习模型原理，CLI-Anything 提供工具接口，Firecrawl 负责公开资料采集，AutoClip 交付可复核的内容。

行动优先级：若只有 90 分钟：先投入 45 分钟做 LangChain4j Tool 测试，再用 45 分钟验证 AutoClip 自有视频切片；OLake 不可降级问题列为下一次专项架构实验。所有实验使用自有、公开或虚构数据，不接生产凭据。
