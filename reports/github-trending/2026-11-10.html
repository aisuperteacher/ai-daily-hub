04 / 六项技术趋势与架构判断

1. AI Agent 从功能堆叠走向执行可靠性。 OpenMausBot 管理会话、凭据与任务，agent-browser 用结构化页面观察和执行；两者都需要权限最小化与回放审计。
2. 企业 Java AI 的关键升级是会话、协议与 Tool 契约。 Spring AI RC2 与 AgentScope Java 让 MCP、事件、状态恢复更系统化，但外部业务操作必须保留事务和幂等。
3. Skills 与工作流必须按真实任务选择。 Anthropic Skills 可提供可复用知识，但脚本执行、不同目录许可与上下文开销需要审计。
4. 推理基础设施的性能声明必须拆开测。 Dynamo 的 P95、TTFT、吞吐和 GPU 资源比单纯支持某个模型版本更重要；实验快照不代表稳定版。
5. 设计与内容工具进入 AI 协作阶段。 Astryx 给 Agent 可复用的组件规则，Claude Quickstarts 给应用骨架，GBrain 给跨会话事实；分别对应界面、应用与记忆层。
6. 热度与成熟度不能混用。 Sherlock 的高日增长是开发者关注信号，MuJoCo、OpenRewrite 的长期维护与工程验证更适合支撑长期架构选型。
