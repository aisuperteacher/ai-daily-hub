二、OpenAI｜Java SDK 4.99.0：12 小时缓存与 Cache Write 成本治理

发布日期：2026-11-04 04:03 UTC（北京时间 12:03）｜版本：v4.99.0｜正式版｜优先级：必看

官方来源：OpenAI Java SDK v4.99.0 · Prompt Caching · Responses API

1）内容与版本

变化 工程意义
12 小时 Responses 缓存 稳定 Prompt 前缀可配置更长 TTL
Cache Write 用量字段 普通输入、缓存读取和缓存写入需要拆开计量
GPT-6 Rosalind 模型目录 增加此前已公告的受控研究模型标识
Project Service Tier Settings 增加项目服务档位设置 API 定义
生成文件所有权文档 澄清 SDK 生成文件的维护规则

SDK 增加模型目录不代表用户账户已获得访问权限。 Rosalind 的研究权限需单独审批，本次不是它首次发布。

2）核心机制：Prompt Cache 与不同 TTL

Prompt Cache 复用稳定上下文前缀的 KV 状态，并非简单缓存整份对话。

Stable System Instructions
          |
          v
Reusable Tool Definitions
          |
          v
Prompt Cache
          |
          +-- Miss -> Cache Write
          |
          +-- Hit  -> Cache Read
          |
          v
Dynamic User Request
          |
          v
Model Inference

官方说明，对支持新缓存配置的 GPT-5.6 及后续模型：30 分钟 TTL 的 Cache Write 按标准输入价的 1.25 倍；12 小时 TTL 按 2.5 倍；Cache Read 采用模型相应较低价格。普通输入仍按正常输入价格。不同类别不应重复计费，也不能将倍数套用所有旧模型。

3）价值、公式和成本边界

总输入相关费用可按不同 Token 类型建模：

[ C=\frac{U P_i+R P_c+W_{30}(1.25P_i)+W_{12}(2.5P_i)}{10^6} ]

其中 U 为普通输入 Token、R 为缓存读取、W30 / W12 为不同 TTL 的缓存写入、Pi 为标准输入单价、Pc 为缓存读取单价。公式仅适用于文档描述的新计费结构，具体价目由 Model ID 决定。

若示例模型标准输入价是每百万 Token 1 美元、缓存读取价是 0.10 美元，则 12 小时 Cache Write 为每百万写入 Token 2.50 美元。**这是假设数值，非指定模型报价。**稳定前缀复用不足时，12 小时缓存可能不经济。

4）适用业务场景

企业 RAG、长上下文 Agent、固定工具 Schema、批量文档处理、重复代码分析和多个会话共用系统说明的 SaaS。不应跨租户混用敏感缓存数据。

5）对 Java / Spring Boot / AI Gateway 的帮助

成本账本至少区分：

provider
modelSnapshot
requestId
cacheMode
cacheTtl
inputTokens
cachedTokens
cacheWriteTokens30m
cacheWriteTokens12h
outputTokens

租户间应按策略隔离敏感数据。官方说明缓存与符合条件的 Zero Data Retention 方案兼容，但具体数据政策和模型仍需核实。

6）实践步骤与验收

测试分支的 Maven 依赖：

<dependency>
  <groupId>com.openai</groupId>
  <artifactId>openai-java</artifactId>
  <version>4.99.0</version>
</dependency>

mvn dependency:tree
mvn test

Responses 缓存请求核心字段示意：

{
  "model": "<SUPPORTED_MODEL_ID>",
  "input": "分析一个脱敏业务需求",
  "prompt_cache_options": {"ttl": "12h"}
}

实际支持依赖模型和 Endpoint。用相同稳定前缀重复调用，分别记录 30 分钟与 12 小时的 Cache Write、Hit、P95、费用；若第三方中转不支持字段，必须准确处理错误。

**验收标准：**缓存命中和写入可区分、费用能核账、输出正确、失败不无限重试。

7）优先级、兼容性和迁移成本

**必看，建议 Java AI Gateway 优先更新成本模型。**这是可选新功能而非要求全部应用迁移缓存方案；按真实命中率判断使用 TTL，不能默认认为更长更省钱。

六、Meta｜F3 Lightning：独立发布与共享计算解耦

原始发布日期：2026-11-03｜官方工程文章历史补录｜优先级：建议看

官方：F3 Lightning

1）内容是什么

Meta 介绍广告机器学习特征系统 F3 Lightning，用于解决多个特征绑定到同一次构建发布、某个特征出错阻塞其他特征的问题。方案让特征独立校验、发布和回滚，而运行时仍能共享计算结果。

2）核心机制

Feature A ----\
               \
Feature B ------> Independent Release
               /
Feature C ----/
                    |
                    v
           Shared Execution Plan
                    |
                    v
           Deduplicated Runtime

基于计算语义的稳定节点标识、运行时共享拓扑、去重计算和统一 Buffer 提高复用度，让错误影响范围限制在有依赖关系的节点。

3）价值与证据边界

说明独立发布与共享执行并非必然冲突；但指标来自 Meta 内部广告场景，不应外推到普通 RAG 和 CPU 服务。没有统一适用于所有企业的优化百分比。

4）应用场景

推荐系统、风控特征、RAG 特征准备、规则平台、高吞吐数据处理。

5）企业架构价值

可在 Feature Registry 中独立管理 Version/Dependency，在 Runtime 共享重复计算，避免一次大部署阻塞所有业务功能。

6）实践和验收

选择三个内部只读计算模块、其中两个共享相同数据查询，测试独立执行和共享执行的 RPC 次数、P95、CPU、缓存；让一个模块配置失败，确认其余正常。

**验收标准：**失败隔离有效，共享结果准确，优化可以重复测量。

7）优先级与部署边界

建议看。 这是架构实践，不是 Meta AI 消费产品、Llama API 或模型权重及许可证更新。

十二、综合工程判断

本期有三个值得持续跟踪的方向。

第一，模型能力向多协议与多模态深化。 Hy4 为企业提供新的评测候选，但协议兼容不能替代 Tool Schema、Thinking、视觉输入和成本回归。

第二，AI Gateway 的成本模型正在变复杂。 12 小时缓存与独立 Cache Write 计量要求企业不能再把所有输入 Token 按单一费率核算。

第三，Agent Runtime 的安全边界正由 Prompt 转向执行层。 Qwen Code 对仓库 Hooks、远程连接、PR 容器及恢复的治理是企业必须建设的能力。

Meta F3 Lightning 同样表明独立发布与共享执行可以并存，但要明确依赖、权限、状态和失败隔离。
