01｜Cloudflare Workers AI：24 款模型计划于 11 月 20 日停止服务

P0 AI 推理 / API 兼容性 / 中国模型生态 · 公告 11 月 5 日；生效 11 月 20 日

新闻摘要

Cloudflare 确认其 Workers AI 模型目录将进行批量清理，涉及 16 款大语言模型和 8 款其他类型模型。此前公布的 11 月 15 日退役日期已延后至 11 月 20 日，届时继续调用被移除模型将返回 HTTP 410 Gone 和错误代码 5028。受影响的模型覆盖 DeepSeek、Kimi、智谱、Qwen、Llama 和部分语音、视觉、图像模型。这是 Cloudflare Workers AI 上特定模型 ID 的服务变化，不是相关模型在所有平台的全球退役。

关键事实与数据

维度官方数据与边界
LLM 数量16
其他模态模型8
生效时间2026-11-20
HTTP 错误410 Gone / 5028
大模型替代候选@cf/deepseek-ai/deepseek-v4.1-flash-1017；@cf/zai-org/glm-5.3
小模型替代候选@cf/google/gemma-4-26b-a4b-it；@cf/qwen/qwen3.8-27b
受影响示例@cf/moonshotai/kimi-k2.7-code；@cf/zai-org/glm-5.2；@cf/qwen/qwq-32b

为什么值得关注与架构影响

如果 Java AI Gateway 或 Worker 将模型 ID 写死在业务配置，退役可以在业务代码完全没有变化时造成调用失败。迁移应沿着“业务接口 → 模型注册表 → 能力与成本匹配 → 主模型 → 故障分类 → 备用模型”执行，不能只按模型厂商名字直接替换。还需核对 Tool Calling、JSON Schema、上下文限制、延迟和费用，避免请求成功却返回错误业务字段。

今日行动建议

在生产与预发布环境的配置、Worker 源码和环境变量中检查退役模型 ID。为候选替代模型执行固定回归用例，覆盖正常生成、函数调用、结构化输出、超时、429 限流、410 退役和成本比较。将 HTTP 410 归类为永久性资源或配置错误，不能无休止重试同一模型。

风险判断

官方推荐替代模型并不保证价格、功能、性能、模型输出或合规条件等价。新模型应经过灰度验证，不能未经测试直接切换全部生产流量。

官方／研究来源： Cloudflare 官方退役公告

02｜Cloudflare Workers：11 月 17 日模块注册表和取消信号默认行为调整

P0 JavaScript 运行时 / Node.js 兼容 / AI Gateway · 公告 11 月 2 日；兼容日期条件 11 月 17 日

新闻摘要

Cloudflare 公布，使用 2026-11-17 或更晚兼容日期的 JavaScript Workers，将默认使用新的模块注册表并改善 JavaScript 与 Node.js 模块兼容。满足该兼容日期条件的 Workers 还会默认通过 request.signal 感知客户端断连，便于取消不再需要的下游请求。两项变化是由 Worker 的 compatibility date 触发，并不意味着所有现有项目在 11 月 17 日当天都会被强制切换。

关键事实与数据

维度官方数据与边界
触发条件compatibility_date ≥ 2026-11-17
Module Registry新的模块注册表默认启用
require()可在条件允许时加载 ES 模块，但相关依赖不能使用顶层 await
import.meta支持获取模块定位与解析信息；应检查打包器转换
request.signal可感知客户端断连；取消需显式传递 AbortSignal
保持旧模块加载行为legacy_module_registry
关闭新请求取消行为disable_request_signal

为什么值得关注与架构影响

在 Worker 担当 AI API 转发层时，用户提前关闭网页而远端 AI 任务仍在执行，可能导致无效资源消耗。新的断连信号有助于控制成本，但不是任何模型服务端都会自动停止计算；只有支持取消并收到信号的下游操作才会停止，计费边界仍由服务端决定。模块注册表则可能影响旧版打包逻辑、ESM/CJS 混用及顶层 await 依赖。

今日行动建议

先检查 wrangler.toml 或 wrangler.jsonc 中的 compatibility_date，不要无条件升到最新日期。测试旧模块导入、require() 调用、顶层 await 与打包后的模块引用；再模拟浏览器中断流式 AI 回答，检查上游调用终止、日志和实际计费。

风险判断

兼容日期升级可能连带激活多项行为变化，单次 HTTP 200 测试不足以证明兼容。request.signal 并不会自动向每个 fetch 或外部工具透传，应明确传递 signal。

官方／研究来源： Cloudflare Changelog：11 月 17 日两项默认行为

03｜AWS AgentCore：模型故障转移与现有业务工作流纳入 Agent 基础设施

P1 企业 AI / 多模型容灾 / 工作流治理 · 11 月 11 日官方十月更新回顾

新闻摘要

AWS 于 11 月 11 日发布技术总结，介绍 Bedrock AgentCore CLI 1.0 正式版、AgentCore Gateway 模型故障转移，以及将 AWS Step Functions 工作流作为 Agent 工具的能力。Gateway 可以在主模型限流或不可用时按预设策略切换后备目标，并利用熔断机制跳过故障目标。Step Functions 允许企业复用已经确定的审批、资格检查和执行规则，而不是把它们全部放进 Prompt。文章总结的是十月发布的能力，不是将全部功能宣布为 11 月 11 日新上线。

关键事实与数据

维度官方数据与边界
AgentCore CLI1.0 GA；可管理 Harness、Runtime、Memory、Identity、Gateway 等
Model Fallback按策略选择后备模型或提供商
Circuit Breaker故障目标暂时被跳过
Step Functions已有 Standard 和 Express 工作流可以通过 Gateway 暴露为工具
Private VPC Target可通过自有私有 CA 证书访问受保护目标
Structured OutputsClaude 模型在 Bedrock 中支持 Schema 对应的结构化输出

为什么值得关注与架构影响

企业 AI 架构应将模型决策与可验证的业务执行分开。退款示例为“用户申请 → Agent 识别 → RefundWorkflow → 权限核验 → 幂等控制 → 审批规则 → 退款执行 → 审计”，即使出现 Prompt Injection，也不能绕过后续规则。这一原则同样适用于 Java 微服务与独立工作流引擎，不需要将整套既有系统迁移到 AWS 才能学习。

今日行动建议

在不连接生产支付系统的测试环境建设订单取消或退款工作流，明确 Agent 的可控范围与不可绕过的业务审批。记录唯一幂等键、身份、审批状态和副作用，测试模型 429、超时、错误 JSON、模型回退以及人工拒绝后的状态恢复。

风险判断

模型推理回退不同于业务动作重试；如果第一次执行已触发真实副作用，第二次重跑可能造成重复退款或扣款。必须引入业务级幂等与审计，不应仅依赖 Gateway。

官方／研究来源： AWS 官方十月 AI Builder 更新总结（11 月 11 日发表）

04｜AgentTorrent：10,944 个 GitHub 项目揭示 Agent Harness 配置与上下文工程

P1 GitHub / AI Coding / Skills / MCP / Hooks · 研究 11 月 11 日

新闻摘要

研究团队发布 AgentTorrent 数据集，覆盖 Claude Code、GitHub Copilot、OpenAI Codex、Cursor、Gemini、OpenCode 六类工具相关的项目。数据收集了 10,944 个工程项目、62,374 份配置工件、27,593 份规划文档，以及超过 120 万次带 AI 工具署名的提交。研究还在 388 个项目中同时观察到配置工件、规划文档与 AI 署名提交，使研究者能够分析指令导入、冲突和实际执行关联。这是可供进一步研究的数据基础，而不是某种 Harness 能提升多少生产力的因果证明。

关键事实与数据

维度官方数据与边界
工程项目10,944
配置工件62,374
规划文档27,593
带 AI 署名的提交超过 1,200,000
三类工件交集项目388
研究覆盖工具Claude Code、Copilot、Codex、Cursor、Gemini、OpenCode

为什么值得关注与架构影响

AI 编程交付质量不仅取决于模型或 Prompt，还与仓库的上下文文件、Skills、Hooks、MCP 配置、权限策略和 CI 验证机制有关。若 AGENTS.md 要求先测试而某个 Skill 允许直接跳过，就会出现指令冲突；若工具权限可运行敏感操作却缺乏审计，风险还会传递至生产环境。重点不在统计有多少配置文件，而在这些文件是否形成一致的执行契约。

今日行动建议

整理项目中所有 Agent 配置文件、引用、作用域、允许工具、禁止命令与验证要求；在 CI 中检查配置冲突、失效引用及潜在密钥泄露。选一个固定真实 Bug 修复任务，对比配置治理前后任务通过率、返工量、人工审查时间和工具权限违规次数。

风险判断

研究结果受项目样本、配置检测规则和 AI 署名方式影响。388 个项目是特定可观测资料交集，不代表剩余项目没有 Agent；统计规模不能直接当作效果增益。

官方／研究来源： AgentTorrent 论文与数据说明

05｜英国 Starling Bank：自然语言支付让 AI 与银行交易流程衔接

P1 数字银行 / Agentic Payments / 交易授权 · 公告 11 月 13 日；零售推广计划至年底

新闻摘要

英国 Starling Bank 公布 Talk to transact 支付能力，用户能够通过自然语言文字或手机语音输入描述转账或付款意图。Starling Assistant 负责解析指令、准备交易信息，最终仍由用户在 App 中点击批准。银行计划在 2026 年底前逐步推广至零售客户，未来还将拓展至上传发票图片的小企业支付场景。这不是让 AI 无需授权就自由动用银行账户资金。

关键事实与数据

维度官方数据与边界
公告日期2026-11-13
零售推广计划2026 年底前
输入自然语言文字或手机键盘语音输入
用户授权在 App 内明确点击确认
企业支付场景上传发票图片、识别收款方及金额、等待客户批准
已推出 Smart ToolsStarling 表示共 14 项

为什么值得关注与架构影响

实际可用的 AI 银行业务可拆为“意图解析 → 收款方与金额校验 → 独立交易授权 → 银行支付执行与审计”。模型给出待确认的结构化建议，而账户权限、收款方、限额和最终执行必须由可信交易系统决定。这对金融微服务和 AI 商业产品都具有启发意义：AI 增强交互，不替代账本与风险控制。

今日行动建议

构建不接入真实银行、无真实资金的模拟支付 Agent：输入“给供应商支付 200 元”，生成含收款方和金额的待审批交易，在用户明确批准前不执行。测试金额歧义、收款方重名、重复点击、Prompt Injection、网络超时与交易幂等。

风险判断

官方只是公布分阶段推广计划，不能断言所有用户现已可用。语音便利性不是强身份认证，收款方核验、反欺诈与人工授权都不能省略。

官方／研究来源： Starling：Talk to transact 官方公告
