01 · 先看到它要解决的问题

你在 feature/payment 改了十几个文件，还没提交；线上支付超时，需要立刻从主线修复。

传统切换分支

一块工作目录，不断 stash → switch → 修复 → switch → pop。上下文中断，还要小心误恢复或冲突。

使用 Git Worktree

不同任务拥有不同目录。原目录未提交的修改留在原地；另开一个目录修 Bug，各自独立编辑、构建、提交。

一句话：Worktree 并不是一份新 clone。它将“共享的仓库历史”与“独立的工作现场”拆开管理。

02 · 真正的底层原理

仓库的数据在共享对象数据库；每个 worktree 有各自的文件、HEAD 和暂存区（index）。点击标签观察哪些部分共享、哪些部分隔离。

◈ 公共 Git 数据 · $GIT_COMMON_DIR

主工作树的 .git/ · 对象库通常不复制

objects/commit · tree · blob
refs/heads/共享分支引用
config默认共享仓库配置

📁 payment-app/

原始 main worktree

feature/payment
独立 HEAD / index / 工作文件

📁 payment-hotfix/

linked worktree A

hotfix/payment
独立 HEAD / index / 工作文件

📁 payment-release/

linked worktree B

release/1.0
独立 HEAD / index / 工作文件

真实结构中，每个附属目录的 .git 通常是一个小文本文件，指向主仓库内 .git/worktrees/<name>/ 的私有元数据。

共享：Git 提交对象、标签及常规分支引用等。某个 worktree 新提交会写入同一个对象库，对应分支引用也在同一仓库中更新。

HEAD 是什么？

当前工作现场指向哪个分支或提交。每个 worktree 有自己的 HEAD，因此可以同时站在不同分支。

index 是什么？

本工作现场的暂存区，记录下一次提交准备纳入的文件内容。git add 只暂存当前 worktree 的改动。

04 · 真实终端里怎么做

以下命令兼容 PowerShell、Git Bash 与常见 Unix Shell。假设当前所在目录名为 payment-app，当前分支为 feature/payment。

① 更新远程主线信息（不改变当前未提交文件）git fetch origin

这里选择 origin/main 作为修复基线。

② 从主线创建独立的修复分支和目录git worktree add -b hotfix/payment ../payment-hotfix origin/main

-b 创建新分支；../payment-hotfix 是另一个真实目录。

③ 进入新目录、修改、测试和提交cd ../payment-hotfix git status git add . git commit -m "fix: payment timeout" git push -u origin hotfix/payment

在团队仓库中通过 Pull Request / Merge Request 合并回主线。推荐确认测试通过后再推送。

④ 返回原目录，删除不再需要的 worktreecd ../payment-app git worktree list git worktree remove ../payment-hotfix

完成后原功能分支的 12 个未提交文件仍在。删除 worktree 不会自动删除其分支。

必会的辅助命令

git worktree list 查看全部；git worktree move 挪动目录；git worktree repair 修复关联；git worktree prune 清理遗留元数据。

看清 .git 的指向

在 linked worktree 里运行 git rev-parse --git-dir 和 git rev-parse --git-common-dir，可观察私有元数据与共享仓库的位置。

05 · 什么时候用哪种方式？

方式工作文件Git 对象库典型场景
git switch同一份目录内切换共享简单、低频的串行任务
git worktree每个任务独立目录同一仓库共享Hotfix、并行功能、多个 AI Agent
git clone独立目录独立仓库对象库（通常）真正需要完整独立仓库环境

注意这些边界：默认不能在两个 worktree 中同时检出同一个本地分支；独立目录不等于独立数据库、端口、依赖缓存或远程分支。每个项目单独安装/构建依赖，并为并行运行的服务分配独立端口和测试数据库。

07 · 给自己一个 10 分钟实验

  1. 找一个已经初始化 Git 的练习项目，在原目录随意修改文件但不要提交。
  2. 运行 git worktree add -b experiment/wt ../wt-demo HEAD。
  3. 在新目录修改一个文件并提交，返回原目录观察：原文件修改仍在，但 Git 提交对象共享。
  4. 分别在两处运行 git status、git worktree list。
  5. 确认新目录没有未提交内容后用 git worktree remove ../wt-demo 清理。

实验说明：这里为了安全从 HEAD 新建实验分支，与前面“从远程 main 进行 Hotfix”的真实工作流不同。主项目无需切换分支，也无需执行 stash。
